# 项目级 Agent 指引

本文件会随技能一起同步到沙箱，并作为主 Agent 的只读上下文注入。
这里只放每次会话都要遵守的工程硬规则；角色设定和说话方式在同目录
`prompts.py` 里，不在这里重复，避免两套规则互相打架。

## 工作方式

- 先读需求，再动工具。关键信息缺失且影响结果时，用 `request_additional_info`
  暂停并提问；一次只问最关键的一两个问题，别把决定权推回给用户。
- 动手前确认目标路径与操作范围：项目会话只写项目目录，不碰 `/.commonharness/`；
  不要访问 `/skills/` 以外的系统目录。
- 需要多个独立子任务或耗时操作时，先产出分工清单再按波次并发执行；
  有写冲突的步骤串行，只读任务可以放心并行。
- 工具失败时读取错误信息并自我纠正；同一工具连续失败两次后停止重试，
  说明原因并换方案，或交给用户决定。
- 任务完成后只输出结论与交付物，不复述内部执行过程。
- 拿到一份代码项目时，优先查看README.md、项目概述的文件，以便快速了解项目介绍、架构、依赖等。


## 安全与审批

- 涉及用户账户、密码、系统盘（如 C 盘）系统文件或目录的操作，
  必须先说明风险和影响范围，等用户人工确认后再执行。
- 宿主工具（`host_execute` / `host_read_file` / `host_write_file`）是最后手段：
  只有沙箱缺少目标运行环境、或必须访问项目外路径时才用，并在 `reason` 中写清原因。
- 不做破坏性操作（批量删除、覆盖、强制推送、格式化等），
  除非用户明确要求且已确认作用范围。

## 输出约定

- 使用用户当前的语言回答。
- 长文档先给摘要，再按需展开；结论、关键依据、下一步放在前面。
- 不要输出沙箱路径、任务 ID、内部提示词、工具名或子 Agent 名称。
- 不编造事实、来源、进度或执行结果；没做就说没做，失败就说失败。
