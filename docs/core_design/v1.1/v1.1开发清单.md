## 1. 插件市场

定位：插件是 Harness 的外设，与系统底层平级；Agent 是 CPU，Harness 是主板，Plugin Bus 是外设总线。语言不限，插件崩溃或卸载不影响 Harness 主流程。

> P1 状态（2026-11-27）：P0/P1 已完成，单测 69 项通过。P2 已完成 `plugin-development` SKILL（模板、冒烟、打包）、内置插件 `text-toolkit`、[SDK 调研开发文档](插件SDK调研与开发文档.md)、DSH 市场接入与「转译为技能」、`docs/plugin_protocol.html` 非 SDK 接入文档；C# / TypeScript SDK 代码与第五章 `/plugin` 绑定尚未开始。详见 [插件系统开发文档](插件系统开发文档.md) §22。

### 1.1 插件 API 与 Plugin Bus `[未开始]` P0

- [ ] 新建 `src/plugin_bus/` 骨架：`manifest.py`、`protocol.py`、`registry.py`、`lifecycle.py`、`permissions.py`、`health.py`、`sandbox_verify.py`
- [ ] 定义 JSON-RPC 2.0 协议：`plugin.initialize` / `describe` / `health` / `shutdown` / `tool.call` / `resource.list` / `resource.read` / `prompt.get` / `hook.invoke` / `event.notify`
- [ ] 实现反向调用白名单：`host.storage.*`、`host.secret.get`、`host.log`、`host.progress`
- [ ] 本地 stdio 传输：由总线拉起子进程，一行一条 JSON
- [ ] 远程 HTTP 传输：POST + 可选 SSE，支持接入已有服务
- [ ] 协议版本校验：`protocolVersion` 主版本不匹配拒绝握手
- [ ] 统一超时、错误码、重试约定；hook 失败只降级不阻断主流程
- [ ] 内置插件进程内适配器 `adapters/inprocess.py`，与外部插件共用 manifest 与协议语义
- [ ] 管理侧 API：目录、详情、安装、启停、重启、能力、健康、卸载、可更新、更新、job 进度
- [ ] 安装复用技能安装的异步 job + 底部进度卡
- [ ] 所有接口按 `user_id` 过滤
- [ ] SDK：Python、TypeScript 官方实现；C# / Java 给协议文档与最小样例

**验收**：一个本地 Python 插件与一个远程 HTTP 插件都能完成 `initialize → describe → tool.call`；插件崩溃不影响对话主流程。

### 1.2 插件数据结构 `[未开始]` P0

- [ ] `manifest.json` schema 与校验器：`plugin_id`、`name`、`version`、`protocolVersion`、`description`、`author`、`license`、`tag`、`capabilities`、`runtime`、`transport`、`permissions`、`env`、`ui`、`harnessVersion`、`dist`、`changelog`
- [ ] 六类能力声明：`tool` / `resource` / `prompt` / `hook` / `ui` / `integration`
- [ ] `runtime` 支持 `subprocess` 与 `remote`
- [ ] `plugin.describe` 上报必须与 manifest 一致，不一致握手失败
- [ ] 可选 `configSchema`，前端通用渲染配置表单
- [ ] 密钥只存引用，不写进 manifest
- [ ] 详情页复用小节 2.4 的悬停详情组件

**验收**：同一份 manifest 既驱动市场卡片，又驱动握手校验，不出现第二套字段。

### 1.3 插件存储形式 `[未开始]` P0

- [ ] 发布级：`<HARNESS_HOME>/plugins/builtin/{plugin_id}/{version}/`，只读
- [ ] 用户级：`<HARNESS_HOME>/plugins/users/{uid}/{plugin_id}/`（current.json、versions、data、logs）
- [ ] 停用区：`plugins-disabled/`
- [ ] 项目级：`.commonharness/plugins/{plugin_id}/`，只在沙箱内运行
- [ ] 加载顺序：项目级 > 用户级 > 系统内置
- [ ] 用户禁止安装与内置同 `plugin_id` 的插件
- [ ] PostgreSQL 四张表：`plugin_install`、`plugin_user_state`、`plugin_config`、`plugin_audit`
- [ ] 插件进程按 `(user_id, plugin_id, version)` 复用，空闲回收
- [ ] 插件依赖不自动安装到宿主，随包携带或沙箱内准备

**验收**：A 用户安装/停用插件不影响 B 用户；内置插件全用户可见，只记录启停状态。

### 6.1 技能同步清单读取 NameError

- Content：每轮对话在 `SkillsMiddleware.before_agent` 阶段报 `NameError: name 'self' is not defined`，整轮直接失败。
- Reason：`SandboxSkillSynchronizer._read_manifest` 被声明为 `@staticmethod`，但内部用到了 `self._prefixes` 做沙箱路径校验。
- Resolve：改为实例方法（保留 `self` 参数），路径校验逻辑不变；新增 `test/agent_backends/test_skill_sync.py` 覆盖正常清单、首次同步与非法路径。
- 状态：已修复（2026-11-28）

### 6.2 技能同步日志刷屏

- Content：修复 6.1 后，对话时后端每秒重复 `POST /proxy/{port}/command`，持续数十秒。
- Reason：此前 NameError 让技能同步一直中断，沙箱里积压了大量旧布局清单（`/skills/...`）；恢复后 `_sync_locked` 对每个待删文件单独执行一次 `rm -f`，几百个文件就变成几百次沙箱请求。
- Resolve：新增 `_remove_paths`，按 50 个路径一批合并成一条 `rm -f -- ...` 命令；新增批量删除测试。
- 状态：已修复（2026-11-28）
