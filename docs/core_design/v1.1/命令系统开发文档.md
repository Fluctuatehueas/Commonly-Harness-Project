## 1. 背景与目标

用户在会话界面里输入 `/` 时，应当像使用 Trae / MineCraft 控制台一样，快速表达三类意图：

1. **执行操作**：删除会话、撤回上一轮、重试、切换思考/联网、导出会话。
2. **绑定资源**：指定下一轮使用哪个 Agent、组、技能、MCP、插件、任务流。
3. **查询信息**：命令列表、系统就绪状态、知识库连接、当前绑定、Token 用量。

目标不是做一个通用脚本终端，而是：

- 让用户**少点鼠标**就能完成高频操作；
- 让“本轮用什么资源”变成**输入框里的显式约束**，而不是靠模型猜；
- 让命令解析结果与提示词、工具集**真正联动**，不是只把文本拼进消息；
- 让 Agent 也能通过同一套只读命令查询系统信息，避免重复造工具。

### 1.1 非目标

- 不执行任意 Shell / 系统命令；命令只调用 Harness 内部服务。
- 不做通用插件式命令市场；命令清单由宿主维护。
- 不持久化“命令消息”到会话历史；命令回执是本轮本地视图。
- 不把 `/` 变成唯一的输入方式；普通文本输入行为不变。

## 2. 现状盘点与可复用资产

| 能力 | 现状 | 命令系统复用方式 |
| :-- | :-- | :-- |
| 输入框 | `ChatView.vue` 的 `el-input type="textarea"`（约 2233 行），`Enter` 直接 `submit()` | 替换为 `CommandComposer`，普通文本模式行为不变 |
| 发送 | `stores/chat.ts::send(text, attachments)` 组装 `/chat/stream` 请求 | 增加 `binding` 字段透传，不改 SSE 链路 |
| 请求字段 | `ChatRequest` 已有 `agent_id` / `group_id` / `flow_id` | `/agent`、`/taskflow` 直接复用 |
| Agent 图缓存 | `agent_loader.get_agent_for_user` 缓存键 `agent_id:group_id:integration_server_id` | 绑定资源时缓存键追加 `binding_hash` |
| MCP 过滤 | `main_agent.py` 用 `context.capabilities.mcp_server_ids` 决定 MCP 工具 | 绑定 `mcp_ids` 作为本轮覆盖值 |
| 插件工具 | `plugin_bus/runtime.py::tools_for_main_agent()` 注入全部启用插件 | 增加 `plugin_ids` 过滤参数 |
| 会话删除/重命名 | `stores/sessions.ts::removeSession / renameSession` | `/delete`、`/rename` 直接调用 |
| 撤回 | `POST /chat/{thread_id}/withdraw` + `api/chat.ts::withdrawLatestMessage` | `/withdraw` 直接调用 |
| 重试 | `stores/chat.ts::retryLast` / `POST /chat/{thread_id}/retry` | `/retry` 直接调用 |
| 技能安装 | `POST /skills/download-url` 返回异步 job | `/skill get` 复用 job + 进度卡 |
| 插件安装 | `POST /plugins/install` 返回异步 job | `/plugin get` 复用 job + 进度卡 |
| 资源列表 | `/agents`、`/agent-groups`、`/skills`、`/mcp/servers`、`/plugins`、`/task-flows`、`/rag/providers` | 建议面板候选来源 |
| 系统自检 | `GET /settings/readiness` | `/status` |
| 本地提示 | `stores/chat.ts::addNote(text)` 追加不落库的 system 消息 | 命令回执的基础 |
| 本地偏好 | `stores/display.ts` 使用 localStorage | 命令模式开关、命令历史 |

关键约束：**命令只在下一个自然轮生效，不能污染后续轮**。绑定数据必须随发送清空，不能写进会话档案。

## 3. 交互模型

### 3.1 触发与模式

- 命令模式默认开启，设置页「对话控制」分组提供开关（与轨迹显示开关同级），持久化到 `localStorage.harness.commandMode`。
- 仅当光标所在位置满足以下条件时弹出建议：
  - 行首，或前一个字符是空白；
  - 当前未处于 IME 组合输入（`compositionstart` 到 `compositionend` 之间）；
  - 输入框未处于禁用态（`chat.sending` 时除 `/stop` 外不可用）。
- 关闭命令模式后，`/` 就是普通字符，建议面板不出现。

### 3.2 语法

```text
command  := "/" name (WS arg)*
arg      := bare | "\"" string "\""
flag     := "-" letter | "--" name ("=" value)?
```

- 命令名大小写不敏感，落库与展示统一小写。
- 参数含空格必须用双引号；未闭合引号在提交时提示语法错误，不发送。
- `-f`、`-team`、`-use` 等短横线参数按命令定义解析。
- 未知参数不阻断执行，只在回执里给出警告（避免用户被卡住）。

### 3.3 建议面板

三级候选：

1. **命令名**：`/` 后展示全部命令，按 `category` 分组（操作 / 资源 / 查询 / 安装）。
2. **资源候选**：命令后输入空格，展示该资源的可选条目（名称、状态、一句话说明）。
3. **参数/标志**：命令定义的 flags 与固定枚举（如 `on|off`、`md|json`）。

键盘映射：

| 按键 | 行为 |
| :-- | :-- |
| `↑` / `↓` | 移动候选 |
| `Tab` | 补全当前候选，不提交 |
| `Enter` | 有候选时选中候选；无候选时提交 |
| `Esc` | 关闭面板；再按一次退出命令模式（不删输入） |
| `PgUp` / `PgDn` | 翻页 |
| 鼠标 | 单击选中；悬停高亮 |

### 3.4 提交行为矩阵

| 命令类型 | 有剩余文本 | 无剩余文本 |
| :-- | :-- | :-- |
| 查询类（`/help` `/rag` `/status` `/binding`） | 先执行查询，再发送文本 | 只展示回执，不调用模型 |
| 绑定类（`/agent` `/skills` `/mcp` `/plugin` `/taskflow`） | 先写入本轮绑定，再发送文本（带 `binding`） | 只更新绑定并提示“已绑定，请输入消息” |
| 操作类（`/delete` `/withdraw` `/retry` `/new` `/rename`） | 拒绝混用并提示；除 `/rename` 参数外不发送文本 | 直接执行 |
| 开关类（`/think` `/web`） | 先切换，再发送文本 | 只切换并提示 |
| 安装类（`/skill get` `/plugin get`） | 启动安装 job；`IsUse=true` 时绑定下一轮，剩余文本按绑定类处理 | 启动 job 并展示进度卡 |

### 3.5 确认与回执

- 破坏性命令（`/delete`、`/clear`）必须二次确认；`/delete -f` 跳过确认，但需在输入时显式输入，不能由历史记录回放自动执行。
- 命令回执以**本地卡片**渲染在会话流中：
  - `kind=command`，包含命令原文、状态（成功/失败/警告）、表格或文本内容；
  - 不写入后端历史，刷新后消失；
  - 失败时红色边条 + 错误原因 + 可复制的命令示例。
- 安装类命令复用现有底部进度卡，不再造第二套进度 UI。

### 3.6 绑定生命周期

```text
用户输入 /mcp slack
  → 输入框内生成芯片「/mcp slack」
  → 绑定表 binding.mcp_ids = ["slack"]
  → 绑定条展示：本轮 MCP：slack（可点 × 解除）
  → 用户输入正文并 Enter
  → 请求体携带 binding
  → 发送成功后立即清空绑定条
  → 下一轮无绑定
```

- 绑定按会话隔离，存内存 + 草稿同目录的 localStorage（`harness.binding.{threadId}`），切走再切回时可恢复。
- 新建会话、删除会话、发送成功、点击 × 均清空绑定。
- 同一资源重复绑定幂等；不同类型互不影响。

## 4. 命令清单

### 4.1 基础命令（清单 5.2 + 常用补充）

原清单 5.2 只要求 `/help`、`/delete`、`/withdraw`、`/rag`；`/retry` 起的条目是本文档建议的常用补充，实施时可以先做清单内四条，再按顺序补齐。

| 命令 | 语法 | 行为 | 复用接口 |
| :-- | :-- | :-- | :-- |
| 帮助 | `/help [command]` | 无参列出全部命令；有参展示用法、参数、示例 | 后端命令目录 |
| 删除会话 | `/delete [-f]` | 删除当前会话；无 `-f` 弹确认 | `sessions.removeSession` |
| 撤回 | `/withdraw` | 撤回最新一条用户消息；返回 `removed=false` 时提示该轮未落检查点 | `withdrawLatestMessage` |
| 重试 | `/retry` | 重试最后一条最终回答；运行中、非最后一条拒绝 | `chat.retryLast` |
| 中止 | `/stop` | 中止当前流式生成 | `chat.stop()` |
| 新建 | `/new` | 新建会话，保留当前 Agent/组选择 | `sessions.createSession` |
| 重命名 | `/rename <title>` | 重命名当前会话 | `sessions.renameSession` |
| 知识库 | `/rag` | 表格展示 Provider、类型、启用状态、最近连接时间、文档数 | `GET /rag/providers` + `knowledge/stats` |
| 状态 | `/status` | 后端连通、LLM 配置、沙箱模式、当前会话 Token / 上下文占用 | `/settings/readiness` + `/history/{id}/usage` |
| 用量 | `/token` | 仅展示 Token 与上下文占用 | 同上 |
| 思考 | `/think [on\|off]` | 切换思考模式，无参展示当前值 | `settings` store |
| 联网 | `/web [on\|off]` | 切换联网搜索 | `settings` store |
| 复制 | `/copy` | 复制最后一条助手回答 | 浏览器剪贴板 |
| 导出 | `/export [md\|json]` | 导出当前会话为 Markdown / JSON 文件 | 前端 Blob |
| 清屏 | `/clear` | 仅清空当前页面消息视图，不删后端历史；必须确认 | 前端视图 |

### 4.2 资源命令（对应清单 5.3）

清单 5.3 要求 `/agent`、`/skills`、`/mcp`、`/plugin`、`/taskflow`；`/binding` 是补充命令，用于回显本轮绑定。

| 命令 | 语法 | 行为 |
| :-- | :-- | :-- |
| Agent | `/agent [name] [-team] [team]` | 无参列出 Agent 与组；有参绑定本轮 Agent；`-team` 后紧跟组名并绑定组；`/agent default` 重置 |
| 技能 | `/skills [name\|off\|list]` | 无参列出技能；有参绑定本轮技能（软绑定）；`off` 清空 |
| MCP | `/mcp [name\|off\|list]` | 绑定本轮 MCP 服务（硬过滤）；`off` 恢复默认全部启用 |
| 插件 | `/plugin [name\|off\|list]` | 绑定本轮插件（硬过滤）；`off` 清空 |
| 任务流 | `/taskflow [name\|off\|list]` | 绑定本轮任务流，走既有 `flow_id` 路由 |
| 绑定总览 | `/binding` | 展示当前会话本轮绑定，可一键清空 |

资源命名的容错：

- 优先精确匹配 `id`；其次匹配 `name`（大小写不敏感）；再次唯一前缀匹配。
- 多个同名/多候选时返回候选表并提示“用完整名称重试”，不静默取第一个。
- 资源被停用/未就绪时允许绑定，但回执给出警告（例如 MCP 未连接、插件 unhealthy）。

### 4.3 P1 安装命令（对应清单 5.4）

| 命令 | 语法 | 行为 |
| :-- | :-- | :-- |
| 下载技能 | `/skill get <url> [IsUse]` | 校验 http(s) → `POST /skills/download-url` → 进度卡；`IsUse=true` 时安装完成后绑定下一轮 |
| 下载插件 | `/plugin get <url> [IsUse]` | 校验 http(s) → `POST /plugins/install` → 四道安全闸门 → 进度卡；`IsUse=true` 时绑定下一轮 |

约束：

- 只接受 `http://` / `https://`，拒绝 `file://`、`javascript:` 与本地路径。
- 安装失败必须展示明确原因，不自动重试。
- `IsUse` 默认 `false`；只有 `true` / `use` 才自动绑定，避免“下载即生效”的意外。

### 4.4 扩展常用命令（建议新增，P1/P2）

以下为本文档建议拓展的高频命令，按优先级标注，不与 v1.1 原清单冲突。

| 命令 | 优先级 | 说明 |
| :-- | :-- | :-- |
| `/history [n]` | P1 | 最近 n 条命令历史（localStorage，默认 10），支持 `↑` 调出 |
| `/pin` / `/unpin` | P1 | 置顶 / 取消置顶当前会话 |
| `/archive` | P1 | 归档当前会话，复用会话面板逻辑 |
| `/agent list` | P1 | 仅列出 Agent（不绑定），等价于 `/agent` 无参 |
| `/mcp status [name]` | P1 | 展示 MCP 连接状态、工具数、最近错误（只读） |
| `/plugin status [name]` | P1 | 展示插件健康、版本、权限（只读） |
| `/skill show <name>` | P1 | 读取技能 SKILL.md 前 N 行预览，不安装 |
| `/project [name]` | P2 | 列出或切换当前项目的会话归属（依赖项目模块） |
| `/trace` | P2 | 打开最近一轮轨迹视图（前端路由跳转） |
| `/model` | P2 | 展示当前 Agent 模型、上下文上限；切换模型不在命令内做 |
| `/mcp enable\|disable\|restart <name>` | P2 | 管理类写操作，与 MCP 页权限一致 |
| `/plugin enable\|disable\|restart <name>` | P2 | 管理类写操作，与插件页权限一致 |

原则：**查询类先做，管理类后做**。写操作命令必须复用控制台同一套接口与确认逻辑，禁止命令系统绕过安全闸门。

## 5. 前后端分工

### 5.1 总原则

| 类型 | 执行方 | 原因 |
| :-- | :-- | :-- |
| 只读查询（help / status / rag / list） | **后端** | 前端与 Agent 共用一份数据口径 |
| 会话与 UI 操作（delete / withdraw / retry / new / rename / clear / copy / export） | **前端** | 涉及确认、路由、本地视图状态 |
| 资源绑定（agent / skills / mcp / plugin / taskflow） | **前端解析 + 后端生效** | 前端负责交互，后端负责工具与提示词裁剪 |
| 安装（skill get / plugin get） | **前端发起 + 后端 job** | 复用现有异步任务与进度卡 |

### 5.2 命令目录接口

`GET /commands/catalog`（只读，5 分钟前端缓存）：

```json
{
  "version": 1,
  "commands": [
    {
      "name": "mcp",
      "aliases": [],
      "usage": "/mcp [name|off|list]",
      "summary": "绑定下一轮使用的 MCP 服务",
      "category": "resource",
      "executor": "frontend",
      "risk": "low",
      "requires_confirm": false,
      "args": [
        { "name": "name", "required": false, "candidates": "mcp_servers" }
      ],
      "flags": [],
      "examples": ["/mcp slack", "/mcp off"]
    },
    {
      "name": "rag",
      "usage": "/rag",
      "summary": "查看知识库连接状态",
      "category": "query",
      "executor": "backend",
      "risk": "low",
      "requires_confirm": false
    }
  ]
}
```

- `executor=backend` 的命令由 `POST /commands/execute` 执行。
- `executor=frontend` 的命令由前端 `executor.ts` 分发；后端接口直接拒绝，避免绕过确认。

### 5.3 只读命令执行接口

`POST /commands/execute`：

```json
{
  "command": "status",
  "args": [],
  "flags": {},
  "thread_id": "…",
  "user_id": "u_1001"
}
```

响应统一结构：

```json
{
  "ok": true,
  "command": "rag",
  "kind": "table",
  "title": "知识库连接",
  "columns": ["名称", "类型", "状态", "最近连接", "文档数"],
  "rows": [["企业知识库", "internal", "已启用", "2026-11-28 10:12", 128]],
  "text": "",
  "warnings": [],
  "meta": {}
}
```

错误：

```json
{
  "ok": false,
  "command": "mcp",
  "error": {
    "code": "COMMAND_EXECUTOR_MISMATCH",
    "message": "该命令由前端执行，不能通过后端接口调用"
  }
}
```

### 5.4 ChatRequest 扩展

```json
{
  "message": "把这份周报改成表格",
  "thread_id": "…",
  "agent_id": "writer",
  "group_id": "",
  "flow_id": "",
  "binding": {
    "skills": ["frontend-design"],
    "mcp_ids": ["mcp-slack"],
    "plugin_ids": ["text-toolkit"]
  }
}
```

校验规则：

- `binding` 整体可选；字段缺省 = 不限制。
- `skills` 最多 8 个，名称必须存在于当前用户可见技能（builtin + 用户）。
- `mcp_ids` 最多 8 个，必须是当前用户已启用 MCP。
- `plugin_ids` 最多 8 个，必须是当前用户已启用插件。
- 任一资源不存在返回 422，并列出不合法项；不做静默忽略。
- `agent_id` / `group_id` / `flow_id` 继续使用既有字段，不放进 `binding`。

## 6. 绑定生效机制（后端）

### 6.1 MCP：硬过滤

- 现状：`main_agent.py` 用 `context.capabilities.mcp_server_ids or None` 决定加载哪些 MCP 工具。
- 改动：`binding.mcp_ids` 非空时覆盖该值；为空时维持 Agent 档案配置。
- 效果：模型本轮只能看到所选 MCP 的工具；其他 MCP 工具不注入，减少上下文与误调用。

### 6.2 插件：硬过滤

- 现状：`plugin_bus/runtime.py::tools_for_main_agent()` 注入全部启用插件。
- 改动：签名增加 `plugin_ids: list[str] | None = None`；非空时只返回这些插件的工具、资源工具、提示词与 hook。
- 过滤范围：
  - 工具代理与 `plugin_resource_*` 资源目录；
  - `prompt_section` 注入；
  - `PluginHookMiddleware` 只调度所选插件的 hook；
  - 生命周期事件（崩溃、重启）不受影响，仍按插件维度记录。

### 6.3 技能：软绑定

技能采用渐进式加载，硬隔离会破坏内置/用户双源同步与子 Agent 视图，因此 v1.1 采用软绑定：

- 在系统提示追加独立段落：

```text
## 本轮指定技能
- frontend-design：<SKILL.md 摘要，最多 4000 字符>
```

- 多个技能总长上限 8000 字符，超出按声明顺序截断并写 warning。
- 不隐藏其他技能；只强化“本轮优先按该技能执行”。
- 若技能不存在或已停用，返回 warning，不阻断发送。

### 6.4 Agent / 组 / 任务流

- `/agent <name>` → `chat.selectedAgentId`，请求体 `agent_id`。
- `/agent -team <group>` → `chat.selectedGroupId`，请求体 `group_id`。
- `/taskflow <name>` → 请求体 `flow_id`，沿用现有显式任务流路由。
- 三者在现有会话绑定逻辑上工作，不新增持久化字段。

### 6.5 图缓存与淘汰

`agent_loader.get_agent_for_user` 当前缓存键：

```text
agent_id:group_id:integration_server_id
```

绑定存在时扩展为：

```text
agent_id:group_id:integration_server_id:binding_hash
```

- `binding_hash` 为排序后资源列表的 8 位哈希；空绑定不追加，保持原行为。
- 带绑定的图标记为 **ephemeral**，每用户最多保留 8 张，LRU 淘汰；避免用户反复绑定导致图无限增长。
- 绑定只影响本轮，图虽然被缓存，但不会在没有绑定的请求中被选中。

### 6.6 Agent 侧命令工具

新增主 Agent 工具 `harness_command`：

```json
{
  "name": "harness_command",
  "description": "查询 Harness 系统信息（只读）。支持 help/status/rag/token 与资源列表查询；不执行删除、安装等写操作。",
  "parameters": {
    "type": "object",
    "properties": { "command": { "type": "string" } },
    "required": ["command"]
  }
}
```

- 内部调用 `src/commands/service.py`，与 `POST /commands/execute` 共用处理器。
- 只允许 `risk=low` 且 `executor=backend` 的命令；其他命令返回 `COMMAND_NOT_ALLOWED`。
- 结果以文本表格返回，禁止把大体量 JSON 塞进上下文。
- 工具注册位置：`main_agent.py` 的 `main_tools` 组合处，默认开启，可通过配置关闭。

### 7.2 CommandComposer：输入框内芯片

用户明确要求“命令条目渲染在输入框内、后面可继续跟文本”，因此采用 **contenteditable + 原子芯片**：

```html
<div class="cmd-composer" contenteditable="true" role="textbox">
  <span class="cmd-chip" contenteditable="false" data-cmd="mcp" data-args="slack">/mcp slack</span>
  把这段内容整理成表格
</div>
```

DOM 模型：

- 芯片是不可编辑的 `<span>`，`contenteditable="false"`；
- 芯片后紧接普通文本节点；
- 任意位置可以有多个芯片（例如先 `/mcp slack` 再 `/skills x`）；
- 序列化时按 DOM 顺序拼接 `芯片原文 + 文本`，得到与手输完全一致的字符串。

编辑行为：

| 操作 | 行为 |
| :-- | :-- |
| 在芯片后输入 | 正常插入文本 |
| 芯片内点击 | 光标落到芯片后 |
| Backspace（芯片后无文本） | 整块删除芯片并同步绑定表 |
| Delete（芯片前） | 整块删除芯片 |
| 方向键 | 跳过芯片，不进入内部 |
| 粘贴 | 一律按纯文本插入，避免带入 HTML |
| IME | 组合期间不解析、不弹建议，`compositionend` 后再解析 |
| Enter（无候选） | 提交 |
| Shift+Enter | 换行（保持多行输入） |

序列化与解析：

```ts
interface ParsedCommand {
  raw: string          // /mcp slack
  name: string         // mcp
  args: string[]       // ["slack"]
  flags: Record<string, string | boolean>
  start: number
  end: number
}

function serializeComposer(el: HTMLElement): {
  text: string
  commands: ParsedCommand[]
  rest: string         // 去掉命令后的正文
}
```

- 提交时以 DOM 序列化为准，不依赖输入过程中的中间状态。
- 命令文本不会进入 `message`；`rest` 为空时不调用模型。

降级方案：

- 断言 `document.execCommand` 不用于编辑；只使用标准 DOM API。
- 若 `contenteditable` 初始化失败，回退到原 `el-input textarea`，命令以“上方芯片条 + 纯文本”展示，功能不缺失。
- Electron 与浏览器使用同一实现；悬浮助手窗口复用 `CommandComposer`。

### 7.3 建议面板

- 锚点：优先取光标位置的水平坐标；面板**默认显示在输入框上方**（`bottom: calc(100% + 6px)`），避免被底部输入区或助手窗口裁切。
- 定位：水平方向按光标位置并做左右边界收敛；高度超过 42vh 时内部滚动。
- 尺寸：宽度 320~420px，最大高度 280px，内部滚动。
- 内容：
  - 命令项：名称、usage、一句话说明、分类标签；
  - 资源项：名称、状态点（启用/停用/异常）、副标题（MCP 工具数、插件版本、技能来源）；
  - 空结果：显示“未找到匹配项”，并提示可用 `/help`。
- 性能：候选列表按命令来源分别缓存 30 秒；输入过滤在前端完成，不再请求后端。

候选来源：

| 命令 | 数据源 |
| :-- | :-- |
| `/agent` | `fetchAgents()`，组用 `fetchAgentGroups()` |
| `/skills` | `fetchSkills({ page_size: 100 })` |
| `/mcp` | `fetchMcpServers({ page_size: 100, enabled: true })` |
| `/plugin` | `fetchPlugins()` |
| `/taskflow` | `fetchTaskFlows(1, 100)` |

### 7.4 结果终端渲染

命令结果不再插入消息流，而是统一进入**唯一一个全息终端**：

- 终端固定在会话右下角（`CommandTerminal.vue`），同一时刻只保留最新一条命令结果；
- 标题栏显示 `HARNESS TERMINAL // /命令`、状态（OK/ERR）与手动关闭按钮；
- 正文以终端文本渲染：文本行、对齐后的表格、警告与 `[OK]/[ERR]` 收尾；
- 打字机逐字输出（约 10ms/2 字符），输出中显示光标，结束后可滚动回看；
- 组件卸载或关闭按钮会停止计时器；新命令直接覆盖旧结果并重新播放动画；
- 支持两种挂载形态：主聊天页 `variant=fixed`（固定右下角），悬浮助手 `variant=panel`（助手面板内绝对定位，避免被独立窗口裁切）；
- 主聊天页与悬浮助手共用同一份终端状态，两处的命令结果都能渲染。
- 不再使用会话流内回执卡，避免多条命令把聊天记录撑长。

`/help` 等长表格在终端内折叠滚动，不占用消息区域。

### 7.5 命令状态仓

`src/stores/commands.ts`：

```ts
state:
  modeEnabled: boolean          // localStorage
  catalog: CommandSpec[]        // 后端目录，5 分钟缓存
  history: string[]             // 最近 20 条，localStorage
  bindings: Record<threadId, TurnBinding>
  suggestionsOpen / activeIndex / level

actions:
  toggleMode()
  loadCatalog(force?)
  bind(threadId, kind, value)
  unbind(threadId, kind)
  clearBindings(threadId)
  pushHistory(raw)
  execute(parsed, threadId): Promise<CommandOutcome>
```

绑定存储：

- 内存为主，写入 `localStorage` 键 `harness.binding.{threadId}`，与草稿一起恢复；
- 发送成功后 `clearBindings(threadId)`；
- 切换会话时按 threadId 读取，不跨会话串用。

### 7.6 ChatView / AssistantView 接入

`submit()` 改为：

```text
1. 序列化 composer
2. 解析命令；语法错误 → 回执卡，终止
3. 逐条执行命令：
   - 前端命令：调用 executor
   - 后端命令：POST /commands/execute
   - 绑定命令：写入 commands store
4. 若命令要求终止（/delete /stop /retry /clear）→ 结束
5. rest 为空 → 结束并提示
6. 有 rest → chat.send(rest, attachments, binding)
```

- `chat.send` 增加第三个参数 `binding`，并入 `/chat/stream` 请求体。
- 发送成功后清空绑定与输入（现有“先快照后清空”逻辑保持不变）。
- 流式期间输入框禁用；仅 `/stop` 可用（通过全局快捷键或输入框上方按钮，不允许在禁用输入框里输入）。

## 10. 安全与权限

1. **用户隔离**：所有命令以 `current_user_id()` 过滤；Agent 工具同样。禁止跨用户读取资源候选。
2. **不做 Shell**：命令处理器只调用项目内服务，不接收可执行路径、不拼接 shell。
3. **URL 校验**：`/skill get`、`/plugin get` 仅接受 http(s)，并复用现有下载与四道安全闸门。
4. **破坏性确认**：`/delete`、`/clear` 默认确认；`-f` 只能手动输入，历史回填不得自动带 `-f`。
5. **运行中保护**：`chat.sending` 时除 `/stop` 外拒绝执行命令，避免并发改状态。
6. **资源越权**：绑定资源必须属于当前用户；项目级资源只在该项目会话可见（依赖项目上下文）。
7. **Agent 工具白名单**：`harness_command` 只允许只读命令；写操作返回 `COMMAND_NOT_ALLOWED`，不得由模型代为确认。
8. **输入长度**：命令原文上限 2000 字符；参数总长上限 1000 字符；防止超长输入拖垮解析。

## 11. 可观测与错误处理

- 前端：每次命令执行记录 `console.debug('[command]', name, status, ms)`；失败上报既有前端错误提示，不新增上报通道。
- 后端：命令执行写结构化日志（`command`、`user_id`、`thread_id`、`ok`、`ms`、`error_code`），不记录完整参数中的敏感值。
- 常见错误码：

| 码 | 含义 |
| :-- | :-- |
| `COMMAND_NOT_FOUND` | 命令不存在 |
| `COMMAND_BAD_SYNTAX` | 引号未闭合、参数非法 |
| `COMMAND_EXECUTOR_MISMATCH` | 前端命令误调后端接口 |
| `COMMAND_NOT_ALLOWED` | Agent 调用了写命令 |
| `COMMAND_TARGET_NOT_FOUND` | 资源不存在 |
| `COMMAND_AMBIGUOUS_TARGET` | 资源名匹配到多个候选 |
| `COMMAND_TIMEOUT` | 查询超时 |
| `COMMAND_CONFIRM_REQUIRED` | 缺少用户确认 |

失败回执必须包含“下一步怎么做”，例如：`/mcp slack` 未找到 → “可用：slack-prod、slack-dev；输入 /mcp list 查看全部”。

## 14. 风险与备选

| 风险 | 说明 | 应对 |
| :-- | :-- | :-- |
| contenteditable 复杂度 | 光标、IME、粘贴、撤销栈都容易出问题 | 原子芯片 + 完整序列化；保留 textarea 降级 |
| 图缓存膨胀 | 绑定组合导致 Agent 图数量增长 | `binding_hash` + 每用户 LRU 8 张 |
| 语义模糊 | 用户以为“绑定技能”会禁用其他技能 | 回执明确写“软绑定：优先使用，不禁用其他技能” |
| 命令与消息混用 | 命令文本被发给模型 | 提交前以 DOM 序列化为准，命令段剥离，正文才进入 `message` |
| 多端一致 | ChatView 与 AssistantView 行为不一致 | 共用 `CommandComposer` 与 `stores/commands.ts`，不各写一套 |
| 管理类命令绕过确认 | 直接调用管理接口 | 写操作命令必须走控制台同一套确认与权限，P2 前不开放 |

备选方案（不推荐）：用透明 textarea 叠加高亮层模拟芯片。实现快，但芯片不是原子节点，退格/光标体验与 Trae 差距大，仅在 contenteditable 不可用时兜底。

### 17.2 实现要点

1. 只读命令（`/help` `/status` `/token` `/rag` 与 `list_*`）由后端 `src/commands` 执行，前端与 `harness_command` 共用；写操作与会话操作留在前端。
2. `ChatRequest.binding` 在进入构图前校验，未知技能 / MCP / 插件直接 422；空绑定不改变原行为。
3. Agent 图缓存键追加 `binding_hash`；带绑定的图按用户 LRU 保留 8 张。
4. MCP 绑定覆盖 Agent 档案的 `mcp_server_ids`；插件绑定过滤工具、资源、提示词与 hook；技能走系统提示软注入（单个 4000 字符、总 8000 字符）。
5. 输入框使用 contenteditable + 原子芯片：芯片可整块退格、方向键跳过、粘贴纯文本；IME 组合期间不解析。
6. 输入 `/` 立即展示全部命令；输入命令后继续按空格会给出子命令/固定参数（如 `/skill get`、`/plugin list`）与用法提示，面板底部常驻当前命令 usage。
7. 命令结果统一进入唯一全息终端 `CommandTerminal.vue`：打字机输出、可手动关闭、只保留最新一条；主聊天页固定定位，悬浮助手用面板内定位。
8. 绑定只生效一轮，发送后清空；命令结果不再写入消息流，也不会进入后端历史。

### 17.3 已知边界

- 命令建议覆盖命令名、子命令/固定参数与资源候选；`-f`、`-team` 等标志仍需手动输入。
- 命令结果只保留最新一条并显示在全息终端里，刷新或关闭终端后不再回看历史结果。
- P2 管理类命令（`/mcp enable|disable|restart`、`/plugin enable|disable|restart`）与 `/project`、`/trace`、`/model` 未实现。
- `/skill get`、`/plugin get` 的 `IsUse=true` 通过轮询 job 自动绑定，最长等待约 70 秒；超时只提示后台继续。
- 命令回执不写入后端历史，刷新后消失；这是设计约定，不是缺陷。
- contenteditable 初始化失败时的 textarea 降级尚未单独实现（当前目标浏览器与 Electron 均支持）。
