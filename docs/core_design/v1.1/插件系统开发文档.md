## 1. 背景与范围

v1.0 的扩展手段只有 SKILL 与 MCP：

- SKILL 是提示词与脚本目录，能力边界在「Agent 会不会用」，不能提供可调用的新工具与外部连接。
- MCP 是工具协议，适合接外部服务，但要求对方实现 MCP，且没有 UI、提示词、拦截点、安装市场这一整套生命周期。

v1.1 引入插件，定位是 **Harness 的外设**：

- Agent 是 CPU，Harness 是主板，Plugin Bus 是外设总线。
- 插件与系统底层平级，通过统一协议接入，语言不限（Python / JS / C# / Java）。
- 插件崩溃、超时、卸载只影响单个外设，不阻断对话主流程。
- 内核不改写成「一切皆插件」，不接管 `main_agent` 组合根，也不做 Python 热卸载。

本章要落地的内容：

1. **Plugin Bus**：协议、传输、注册表、生命周期、权限、健康、沙箱验证。
2. **Plugin Protocol**：JSON-RPC 2.0 信封、方法集、错误码、超时与降级约定。
3. **manifest**：市场展示、安装校验、握手注入共用同一份结构。
4. **六类能力**：`tool` / `resource` / `prompt` / `hook` / `ui` / `integration`。
5. **存储**：`plugins/builtin`、`plugins/users/{uid}`、项目级 `.commonharness/plugins`。
6. **PostgreSQL 四张表**：`plugin_install` / `plugin_user_state` / `plugin_config` / `plugin_audit`。
7. **管理侧 API 与市场**：目录、安装、启停、重启、更新、卸载、job、私有源、DSH 导入。
8. **前端**：控制台「插件」三页签、详情、安装进度、UI slot 沙箱 iframe。
9. **安全**：声明权限 → 静态扫描 → 沙箱试运行 → 用户确认。
10. **Agent 自迭代插件**：`plugin-development` SKILL + 沙箱内生成/验证/提议安装。

本期明确不做：

- 官方 Python / TypeScript SDK 的完整实现与公开示例插件（按确认结论，只出协议文档与 SDK 骨架）。
- C# / Java SDK 实现，只有协议文档与目录占位。
- 插件对宿主内部对象的直接访问（不开放 `host.*` 以外的任何宿主接口）。
- 插件依赖自动安装到宿主环境（依赖必须随包携带或声明为沙箱依赖）。
- 不改写 `main_agent` 为插件驱动，不把内置能力做成可热卸载插件。

## 2. 与现有模块的边界

| 维度 | SKILL | MCP | Plugin（本章） |
| :-- | :-- | :-- | :-- |
| 事实源 | `skills/` 磁盘 | `servers.json` + 运行态 | 磁盘 + PG 四表 |
| 提供什么 | 提示词、脚本、渐进式加载 | 工具、资源、提示词（MCP 原生） | 工具、资源、提示词、hook、UI、集成 |
| 运行位置 | 沙箱内脚本 | 宿主侧 stdio / 远程 HTTP | 宿主侧子进程 / 远程 HTTP / 沙箱一次性进程 |
| 安装形态 | ZIP / URL | 粘贴 JSON | ZIP / URL / 远程注册 / 市场目录 |

| 管理入口 | 控制台技能页 | 控制台 MCP 页 | 控制台插件页 + 命令系统 |

| `agent/backends/open_sandbox.py` | 沙箱试运行与项目级插件一次性执行 |
| `agent/middlewares/*` 的 `wrap_model_call` / `wrap_tool_call` | hook 的 before/after model、wrap tool |
| `agent/trajectory_store.py` | 工具调用、hook 降级、插件崩溃事件落轨迹 |
| `agent_loader.reset_agents()` | 插件工具集变化后重建图 |

## 3. 总体架构

```text
┌──────────────────────────── 控制面（Vue 控制台 / 命令系统 / Agent 工具） ────────────────────────────┐
│  api/plugins.py  →  PluginMarket（catalog 索引、安装 job）                                            │
│  api/plugins.py  →  PluginRuntime（按 user 的运行时门面：生命周期、健康、调用）                        │
└───────────────────────────────────────────┬──────────────────────────────────────────────────────────┘
                                            │
┌───────────────────────────────────────────▼──────────────────────────────────────────────────────────┐
│ Plugin Bus（src/plugin_bus/）                                                                          │
│  manifest.py    解析/校验 manifest、版本与权限声明                                                     │
│  protocol.py    JSON-RPC 2.0 信封、方法名、错误码、超时约定                                             │
│  transport/     stdio（宿主子进程）/ http（远程）/ sandbox_stdio（沙箱一次性进程）                       │
│  registry.py    能力注册表 → 注入工具清单、资源目录、提示词                                             │
│  lifecycle.py   状态机 + 状态落库 + 磁盘校正                                                           │
│  permissions.py 总线侧权限拦截 + host.* 白名单                                                         │
│  health.py      心跳、启动探活、退避重启、空闲回收                                                     │
│  scanner.py     包结构与静态扫描                                                                       │
│  sandbox_verify.py  OpenSandbox 内 initialize → describe → smoke + 行为采集                             │
│  adapters/inprocess.py  内置插件进程内适配器                                                           │
│  store.py       PostgreSQL 四表读写                                                                   │
│  catalog.py     市场目录、缓存、私有源、DSH 只读导入                                                   │
└───────────────────────────────────────────┬──────────────────────────────────────────────────────────┘
                                            │
┌───────────────────────────────────────────▼──────────────────────────────────────────────────────────┐
│ 插件进程 / 远程服务（语言无关）                                                                        │
│  本地：manifest.runtime.command + args，cwd = versions/{version}/，env 白名单                          │
│  远程：POST JSON-RPC，可选 SSE                                                                        │
└───────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

三条硬边界：

1. **Bus 只做握手、权限、生命周期、路由**，不理解插件业务。
2. **插件只能看到 manifest 声明的能力和 `host.*` 白名单**，不持有宿主对象、不继承宿主环境变量。
3. **插件故障必须降级**：工具调用返回结构化「插件不可用」；hook 超时或异常只记轨迹并跳过；UI 加载失败只影响该 slot。

## 4. Plugin Protocol

### 4.1 信封

遵循 JSON-RPC 2.0：

```json
{ "jsonrpc": "2.0", "id": "req-1", "method": "tool.call", "params": {} }
{ "jsonrpc": "2.0", "id": "req-1", "result": {} }
{ "jsonrpc": "2.0", "id": "req-1", "error": { "code": -32010, "message": "", "data": {} } }
```

- 通知（无 `id`）只用于 `event.notify`、`host.log`、`host.progress`，不要求响应。
- 所有请求带 `timeout_ms`（放在总线侧配置，不信任插件上报）。
- `id` 由总线生成，按 `(uid, plugin_id, version)` 命名空间隔离。

### 4.2 总线 → 插件

| 方法 | 说明 | 默认超时 | 失败策略 |
| :-- | :-- | :-- | :-- |
| `plugin.initialize` | 握手：协议版本、用户、配置引用、已授权限 | 15s | 失败拒绝启用 |
| `plugin.describe` | 上报能力清单（必须与 manifest 一致） | 15s | 不一致握手失败 |
| `plugin.health` | 健康探针 | 5s | 超时计入失败次数 |
| `plugin.shutdown` | 优雅退出 | 5s | 超时强杀 |
| `tool.call` | 调用工具 | 60s | 返回错误，不影响其他工具 |
| `resource.list` | 列举资源 | 15s | 返回空列表并标记降级 |
| `resource.read` | 读取单个资源 | 30s | 返回错误 |
| `prompt.get` | 获取领域提示词片段 | 10s | 跳过注入 |
| `hook.invoke` | 调用拦截点 | 3s | 记录并跳过，不阻断 |
| `event.notify` | 总线推事件（配置变更、启用/停用） | 不等待 | 忽略失败 |

### 4.3 插件 → 总线（白名单）

只开放四个命名空间，未声明权限直接拒绝：

| 方法 | 权限 | 说明 |
| :-- | :-- | :-- |
| `host.storage.get` / `set` / `list` / `delete` | `storage` | 只允许读写本插件 `data/` 目录，路径穿越拒绝 |
| `host.secret.get` | `secret` | 按名称取用户级密钥，返回明文只在本连接内有效 |
| `host.log` | 无 | 写插件日志，总线截断与轮转 |
| `host.progress` | 无 | 上报长任务进度，前端进度卡可见 |

宿主内部对象、文件系统任意路径、环境变量读取、进程创建均不开放。

### 4.4 传输

| 传输 | 适用 | 实现要点 |
| :-- | :-- | :-- |
| `stdio` | 用户安装的本地插件、内置插件的外部形态 | 一行一条 JSON；总线拉起子进程；stdout 只走协议，stderr 落 `logs/stdio.log` |
| `http` | 远程插件、已有服务接入 | POST JSON-RPC；进度/事件可选 SSE；TLS 必填（localhost 除外） |
| `sandbox_stdio` | 项目级插件、高风险插件 | 每次调用在沙箱内拉起一次性进程，按「initialize → describe → call → shutdown」完成，不做常驻与心跳 |

`stdio` 与 `http` 共用同一套方法名、错误码与超时语义，插件作者不需要区分。

### 4.5 版本协商

- `protocolVersion` 采用 `MAJOR.MINOR`：**主版本不等直接拒绝握手**，不做兼容猜测；次版本只允许插件 ≤ 总线支持的最大次版本。
- `harnessVersion` 采用 semver 范围（`min` / `max`），宿主版本不在范围内时安装阶段就拒绝，并给出明确提示。
- 两条版本轴互不替代：`protocolVersion` 管协议兼容，`version` 管功能迭代。

### 4.6 错误码

JSON-RPC 标准码保留，业务错误使用 `-32001 ~ -32019`：

| 码 | 含义 |
| :-- | :-- |
| -32001 | `PLUGIN_NOT_FOUND` |
| -32002 | `PLUGIN_NOT_READY`（未握手/正在重启） |
| -32003 | `PLUGIN_PERMISSION_DENIED` |
| -32004 | `PLUGIN_TIMEOUT` |
| -32005 | `PLUGIN_CAPABILITY_MISMATCH` |
| -32006 | `PLUGIN_PROTOCOL_VERSION_MISMATCH` |
| -32007 | `PLUGIN_CRASHED` |
| -32008 | `PLUGIN_UNHEALTHY` |
| -32009 | `PLUGIN_PACKAGE_INVALID` |
| -32010 | `PLUGIN_TOOL_FAILED` |

HTTP 管理面统一返回 `{"code": "...", "message": "...", "plugin_id": "..."}`，与 MCP 接口风格一致。

## 5. manifest 与校验

### 5.1 结构

```json
{
  "plugin_id": "context-compactor",
  "name": "上下文压缩器",
  "version": "1.0.0",
  "protocolVersion": "1.0",
  "description": "按会话类型裁剪历史，降低长对话 token 消耗。",
  "author": { "name": "GuiQIHueas", "homepage": "" },
  "license": "MIT",
  "tag": ["上下文压缩和管理", "插件"],
  "source": "community",
  "capabilities": ["tool", "resource", "prompt", "hook", "ui"],
  "runtime": {
    "kind": "subprocess",
    "language": "python",
    "command": "python",
    "args": ["-m", "context_compactor"]
  },
  "transport": { "kind": "stdio" },
  "permissions": ["context:read", "storage", "ui"],
  "env": { "python": ">=3.11" },
  "ui": {
    "slots": [
      { "slot": "chat.sidebar", "title": "上下文占用", "entry": "ui/index.html" }
    ]
  },
  "harnessVersion": { "min": "1.1.0", "max": "1.x" },
  "configSchema": { "type": "object", "properties": {} },
  "like": 100,
  "downloadCount": 100,
  "dist": { "url": "", "sha256": "", "size": 0 },
  "changelog": []
}
```

远程插件只换运行段：

```json
{
  "runtime": { "kind": "remote" },
  "transport": { "kind": "http", "url": "https://example.com/plugin/rpc" }
}
```

随包内置插件（`src/plugin_bus/sys_plugins/`）使用进程内运行段：

```json
{
  "runtime": { "kind": "inprocess", "entry": "plugin:handle" },
  "transport": { "kind": "inprocess" }
}
```

- `runtime.entry` 形如 `模块:属性`，模块相对插件目录，属性缺省时使用模块本身；被指向的对象需实现 `handle(method, params)` 或按协议拆分的 `initialize` / `describe` / `tool_call` 等方法。
- `inprocess` 只允许 `source=builtin`，项目级插件禁止使用，防止项目代码在宿主执行。

### 5.2 校验规则

`manifest.py` 负责解析与校验，失败抛 `PluginManifestError`：

| 字段 | 规则 |
| :-- | :-- |
| `plugin_id` | `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`，同一来源内唯一 |
| `version` | semver |
| `protocolVersion` | `MAJOR.MINOR`，主机主版本必须为 1 |
| `capabilities` | 只能取六类，且与 `runtime` / `transport` 自洽（如声明 `ui` 必须有 `ui.slots`） |
| `permissions` | 只能取标准权限集，去重；未声明即无 |
| `runtime.kind` | `subprocess` / `remote` / `inprocess`（仅 builtin） |
| `transport.kind` | `stdio` / `http`；项目级强制 `sandbox_stdio`（由总线改写，不接受 manifest 指定） |
| `dist` | 本地安装时 `sha256` 必填；市场目录条目必填 |
| `harnessVersion` | 必须覆盖当前宿主版本 |

### 5.3 describe 一致性

`plugin.describe` 返回值：

```json
{
  "plugin_id": "context-compactor",
  "protocolVersion": "1.0",
  "version": "1.0.0",
  "capabilities": {
    "tool": [
      { "name": "compact_history", "description": "", "inputSchema": {} }
    ],
    "resource": [{ "uri": "session://summary", "name": "会话摘要", "mimeType": "text/markdown" }],
    "prompt": [{ "id": "compact-policy", "trigger": "keyword", "keywords": ["压缩", "上下文"] }],
    "hook": [{ "name": "before_model", "priority": 100 }],
    "ui": [{ "slot": "chat.sidebar", "entry": "ui/index.html" }]
  }
}
```

校验规则：

- `describe.capabilities` 出现的类型必须全部在 `manifest.capabilities` 中。
- `tool` / `ui.slot` 名称集合不能与内置工具、MCP 工具、其他插件冲突（工具名统一加前缀 `plugin__{plugin_id}__`）。
- `hook.name` 只能是 `before_model` / `after_model` / `before_tool` / `after_tool`。
- 不一致直接握手失败，状态置 `unhealthy`，写审计。

## 6. 六类能力与注入点

| 能力 | 总线侧 | Agent 侧如何看到 | 本期实现要点 |
| :-- | :-- | :-- | :-- |
| `tool` | `tool.call` 路由、超时、权限 | 注入到主 Agent 工具清单，可直接调用 | 工具名 `plugin__{plugin_id}__{name}`，写轨迹 |
| `resource` | `resource.list` / `resource.read` | 注入资源目录；提供成对的 `plugin_resource_list` / `plugin_resource_read` 工具 | 资源目录进系统提示，正文按需读取 |
| `prompt` | `prompt.get` | 按触发条件拼进系统提示 | 支持 `always` / `keyword` / `capability`；总长 ≤ 2000 字符 |
| `hook` | `hook.invoke` | 中间件拦截，不改主流程 | `before/after_model`、`before/after_tool`，超时 3s，失败跳过 |
| `ui` | 静态资源路由 + slot 注册 | 控制台 slot 内沙箱 iframe | 不进主 bundle，postMessage 白名单 |
| `integration` | 复用 `tool` / `resource` + 凭据 | 与普通工具一致 | 安装时逐条确认外部系统权限，卸载撤销 |

### 6.1 工具注入

- 在 `main_agent.py` 构图时调用 `get_plugin_bus(user_id).tools_for_main_agent(...)`。
- 只读取 manifest 与 LKG 能力快照，**构图阶段不拉起任何插件进程**；首次调用才懒启动。
- 工具描述取 `describe` 结果；`describe` 失败时按 manifest 能力类型给占位工具，调用时返回「插件不可用」。
- 与 MCP 工具、内置工具重名时拒绝注册并写审计，不静默覆盖。

### 6.2 资源注入

- 系统提示追加一段「插件资源」目录：`plugin_id / uri / name / 说明`，只列已启用且有 `resource` 能力的插件。
- 不把资源正文塞进提示，正文通过 `plugin_resource_read` 读取。

### 6.3 提示词注入

- 只注入 `prompt` 能力且声明了触发条件的片段。
- `always`：每轮注入；`keyword`：用户消息命中关键词时注入；`capability`：当前 Agent 档案声明该能力时注入。
- 注入内容进系统提示的独立段落，长度上限 2000 字符，超出截断并记录。

### 6.4 hook

新增 `src/agent/middlewares/plugin_hooks.py::PluginHookMiddleware`，在 `create_deep_agent` 的中间件链中放在 **最内层、`TimeAwarenessMiddleware` 之前**：

- `wrap_model_call`：调用前发 `before_model`，调用后发 `after_model`；只允许修改消息副本，不能替换模型。
- `wrap_tool_call`：调用前发 `before_tool`（可拒绝执行），调用后发 `after_tool`（可改写结果文本）。
- 所有 hook 调用带 3s 超时；异常或超时写轨迹事件 `plugin_hook_degraded`，继续主流程。
- 同一 hook 点按 `priority` 升序执行；默认 100。

### 6.5 ui

- 控制台只渲染 manifest / describe 声明的 slot；未知 slot 忽略。
- 每个 iframe：`sandbox="allow-scripts allow-forms"`，不开放 `allow-same-origin`；响应头带 CSP。
- postMessage 只接受白名单消息：`plugin:ready` / `plugin:resize` / `plugin:event`，校验 `event.origin` 与 `plugin_id`。
- UI 静态资源由 `GET /plugins/{id}/ui/{path}` 提供，只服务已启用插件，路径穿越拒绝。

### 6.6 integration

- 不新增独立调用通道，能力仍通过 `tool` / `resource` 暴露。
- 安装时展示将获得的外部系统权限清单，用户逐条确认；确认结果写 `plugin_config`。
- 凭据走用户级密钥库，manifest 与配置只保留 `${SECRET:...}` 引用；卸载时删除引用并写审计。

## 7. 生命周期与进程管理

### 7.1 状态机

```text
installed → verified → enabled → running → unhealthy → disabled → uninstalled
                │           │          │           │
                │           │          └───────────┴─→ enabled（重启/恢复）
                │           └─→ disabled（用户停用）
                └─→ installed（验证失败，保留包供查看）
```

| 状态 | 含义 | 进入条件 |
| :-- | :-- | :-- |
| `installed` | 包已落盘、未验证 | 安装解压完成 |
| `verified` | 静态扫描 + 沙箱试运行通过 | 两道闸门通过 |
| `enabled` | 用户允许使用、未拉起 | 用户启用或默认启用 |
| `running` | 进程/连接可用 | 握手与 describe 成功 |
| `unhealthy` | 连续失败或心跳超时 | 退避重启 N 次仍失败 |
| `disabled` | 用户停用或系统自动停用 | 用户操作 / `unhealthy` 自动降级 |
| `uninstalled` | 版本目录移除，记录保留 | 卸载完成 |

状态同时落磁盘（`current.json` 只记版本指针）与 PG（`plugin_install.status` / `plugin_user_state.enabled`）。**磁盘是版本与包内容的权威源，PG 是安装记录、启停状态、配置与审计的事实源**；两者不一致时以磁盘包内容为准校正 PG，并写 `repair` 审计。

### 7.2 进程复用

- 复用键：`(user_id, plugin_id, version)`。不同用户不共享进程与内存。
- 进程工作目录固定为 `plugins/users/{uid}/{plugin_id}/versions/{version}/`。
- 环境变量只透传白名单：`PATH`、`PYTHONPATH`（指向插件目录）、`LANG`、`TMPDIR`；**不透传 `DEEPSEEK_API_KEY`、数据库密码、宿主配置**。
- stdout 走协议，stderr 落 `logs/stdio.log`（5 MB × 3 轮转，复用维护任务）。
- 空闲 TTL 默认 300s 回收；单用户并发插件进程上限默认 8；超限调用排队或拒绝。

### 7.3 启动、健康与崩溃

1. 启动：拉起进程 → `plugin.initialize`（15s）→ `plugin.describe`（15s）→ 一致性校验 → `running`。
2. 健康：每 30s `plugin.health`（5s）；连续 3 次失败进入 `unhealthy`。
3. 崩溃：指数退避重启（1s、2s、4s、8s，最多 5 次）；仍失败标记 `unhealthy` 并按用户配置自动停用。
4. Agent 侧看到的是「插件不可用」工具错误，不是整轮对话失败。
5. 所有崩溃、重启、自动停用写 `plugin_audit`，并落轨迹事件。

### 7.4 更新

```text
停旧进程 → 校验新版本包 → 拉起新版本 → initialize/describe → 健康检查 → 原子切 current.json → 回收旧进程
                                                                   └─ 失败：切回旧版本指针并重启旧版本
```

- 版本目录共存，`current.json` 原子替换。
- 只保留最近两个版本，清理旧版本时不影响 `data/`。
- 内置插件跑在宿主进程内，升级随主程序发布，仍需后端重启；UI 扩展刷新页面生效。

## 8. 权限与安全闸门

### 8.1 权限集

| 权限 | 含义 | 总线拦截点 |
| :-- | :-- | :-- |
| `fs:read` | 读插件目录外的指定路径 | `host.storage.*` 之外的读写请求 |
| `fs:write` | 写插件目录外的指定路径 | 同上 |
| `net` | 发起外部网络请求 | 远程 transport、`integration` 调用 |
| `process` | 创建子进程 | 插件内拉起子进程（宿主侧仅记录告警） |
| `context:read` | 读取当前会话摘要与用户配置的非敏感字段 | 注入上下文前 |
| `storage` | 读写插件私有 `data/` | `host.storage.*` |
| `secret` | 读取用户级密钥 | `host.secret.get` |
| `ui` | 注册控制台 slot | slot 注册与静态资源路由 |

规则：

- `permissions` 必须显式声明，未声明即拒绝，不做隐式放行。
- 用户安装时展示权限清单；`secret`、`net`、`process` 属于高风险权限，需要单独勾选确认。
- 项目级插件在沙箱内运行，`fs:*` 与 `process` 映射为沙箱内权限，不作用于宿主。

### 8.2 四道闸门

1. **声明权限**：manifest 校验，缺字段直接拒绝安装。
2. **静态扫描**（`scanner.py`）：
   - 包结构：文件数、总体积（沿用技能包 32 MB 口径）、路径穿越、符号链接、绝对路径解压。
   - 解释型语言：扫描危险调用（`os.system`、`subprocess`、`eval`、`exec`、`ctypes`、裸 `socket` 等），命中只标记风险等级，不直接拒绝。
   - 编译型产物：校验哈希；有签名则验签，不再「见到可执行文件就拒绝」。
3. **沙箱试运行**（`sandbox_verify.py`）：在 OpenSandbox 内按 `initialize → describe → smoke` 执行，采集网络、文件、子进程行为；超时、崩溃、越权直接判失败。
4. **用户确认**：安装前展示能力、权限、来源、外部系统访问范围；高风险项必须逐条确认。

### 8.3 信任分级与运行位置

| 归属 | 来源 | 运行位置 |
| :-- | :-- | :-- |
| 官方内置 | 随版本发布 | 宿主进程内适配器 |
| 集成方私有 | 甲方私有市场 | 按部署策略（宿主子进程或沙箱） |
| 社区 | 自建 catalog | 宿主侧子进程（验证后） |
| 用户本地 | URL / 目录导入 | 宿主侧子进程（验证后） |
| 项目级 | `.commonharness/plugins` | 仅沙箱 |
| Agent 自迭代 | Agent 生成 | 先沙箱，验证后按用户/社区档运行 |

### 8.4 边界说明

- 宿主侧子进程是同等权限的独立进程，**不是 OS 级隔离**；v1.1 靠「装前沙箱验证 + 运行时声明权限」收口。
- 高风险插件只允许沙箱模式运行，详情页必须明示这一点。
- 不继承宿主环境变量；不允许插件读取宿主项目目录；不允许插件直接操作主前端 DOM。

## 9. 存储布局

### 9.1 目录

```text
src/plugin_bus/sys_plugins/{plugin_id}/   # 随包内置插件源码，只读，进程内运行
  manifest.json                           # runtime.kind = inprocess
  plugin.py                               # runtime.entry 指向的入口模块

<HARNESS_HOME>/plugins/
  builtin/{plugin_id}/{version}/            # 版本化内置插件，只读，随版本发布
  catalog/catalog.json                      # 市场目录缓存（部署级）
  users/{user_id}/
    {plugin_id}/
      current.json                          # {"version": "1.0.0", "updated_at": "..."}
      versions/{version}/                   # 包内容（manifest.json + 代码 + ui/）
      data/                                 # 插件私有数据，跨版本保留，跨用户不可见
      logs/stdio.log                        # 进程 stderr
    plugins-disabled/{plugin_id}/{version}/ # 用户停用区
```

- `sys_plugins` 是系统自带插件源码根：只读、不复制到用户目录、不落 `plugin_install`，通过 `InProcessTransport` 在宿主进程内运行；与 `HARNESS_HOME/plugins/builtin` 合并时 `sys_plugins` 优先。
- 内置 `inprocess` 插件只允许 `source=builtin`；项目级插件禁止 `inprocess`，必须在沙箱运行。
- 远程插件没有 `versions/`，只记 endpoint 与配置；卸载只删登记，不碰对方服务。
- 用户不允许安装与系统内置同 `plugin_id` 的插件，防影子覆盖；内置插件可停用不可卸载。
- 项目级插件：`<project_root>/.commonharness/plugins/{plugin_id}/`，不入用户目录、不进控制台插件管理页。

### 9.2 加载顺序与可见性

```text
项目级（仅项目会话） > 用户级 > 系统内置
```

- 同名时高优先级覆盖低优先级；被覆盖项不注入工具。
- 控制台插件页只展示用户级 + 系统内置；项目级只在命令系统 `/plugin` 与项目会话可见。
- 项目级插件不落 PG，目录即事实源；运行记录只进轨迹。

### 9.3 索引

- 已安装索引：扫描 `current.json` + 各版本 `manifest.json`，经 `file_index`（模块名 `plugins`）缓存。
- 市场索引：`plugins/catalog/catalog.json`，内存缓存 10 分钟；请求失败回退缓存并标记 `stale`。
- 索引只存元信息（`id` / `name` / `version` / `path` / `mtime` / `size`），正文不进索引。
- 安装、卸载、启停、更新后主动 `file_index.invalidate("plugins", uid)`。

### 9.4 配额

- 默认 1 GB / 用户、最多 50 个插件、最多 8 个并发插件进程；超限拒绝安装并提示清理。
- 版本保留最近两个；卸载删版本与进程，`data/` 与审计保留。
- 打包脚本负责把 `src/agent/plugins/builtin` 复制到 `<HARNESS_HOME>/plugins/builtin`，版本号与主程序一致。

## 10. PostgreSQL 四张表

`src/plugin_bus/store.py` 使用 `psycopg3` 异步 + `dict_row`，连接复用 `agent.config.POSTGRES_URI`，DDL 逐条执行（与 `task_flow/store.py` 一致）。

```sql
CREATE TABLE IF NOT EXISTS plugin_install (
    user_id        TEXT NOT NULL,
    plugin_id      TEXT NOT NULL,
    version        TEXT NOT NULL,
    source         TEXT NOT NULL,          -- builtin / user / community / integration / remote / project
    runtime_kind   TEXT NOT NULL,          -- subprocess / remote
    transport_kind TEXT NOT NULL,          -- stdio / http / sandbox_stdio
    endpoint       TEXT,                   -- 远程插件地址
    sha256         TEXT,
    status         TEXT NOT NULL,          -- installed/verified/enabled/running/unhealthy/disabled/uninstalled/missing
    installed_at   TIMESTAMPTZ DEFAULT now(),
    updated_at     TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (user_id, plugin_id, version)
);
CREATE INDEX IF NOT EXISTS idx_plugin_install_user
    ON plugin_install(user_id, plugin_id, status);

CREATE TABLE IF NOT EXISTS plugin_user_state (
    user_id        TEXT NOT NULL,
    plugin_id      TEXT NOT NULL,
    enabled        BOOLEAN NOT NULL DEFAULT true,
    current_version TEXT,
    auto_disabled  BOOLEAN NOT NULL DEFAULT false,
    updated_at     TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (user_id, plugin_id)
);

CREATE TABLE IF NOT EXISTS plugin_config (
    user_id        TEXT NOT NULL,
    plugin_id      TEXT NOT NULL,
    config_json    JSONB NOT NULL DEFAULT '{}'::jsonb,
    secret_ref     TEXT,
    updated_at     TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (user_id, plugin_id)
);

CREATE TABLE IF NOT EXISTS plugin_audit (
    id         BIGSERIAL PRIMARY KEY,
    user_id    TEXT NOT NULL,
    plugin_id  TEXT NOT NULL,
    version    TEXT,
    action     TEXT NOT NULL,   -- install/enable/disable/restart/update/uninstall/verify/repair/permission_change
    result     TEXT NOT NULL,   -- ok/failed/denied
    detail     JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_plugin_audit_user
    ON plugin_audit(user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_plugin_audit_plugin
    ON plugin_audit(user_id, plugin_id, created_at DESC);
```

约定：

| 规则 | 说明 |
| :-- | :-- |
| 内置插件不写 `plugin_install` | 磁盘目录即可发现；用户停用时只写 `plugin_user_state.enabled=false` |
| 远程插件写 `plugin_install` | 只记 endpoint / 协议版本 / 状态，无版本目录 |
| 不建插件内容表 | 避免磁盘与数据库两份事实源 |
| 敏感值不落 `plugin_config` | 只存 `${SECRET:...}` 引用；密钥库实现随安全闸门一起做 |
| 缺失记录自愈 | 磁盘有包、PG 无记录时补登记，`action=repair` |
| 记录存在、磁盘缺失 | `status=missing`，列表返回异常态并提示重装 |

## 12. 插件市场

### 12.1 目录格式

`plugins/catalog/catalog.json`：

```json
{
  "version": 1,
  "updated_at": "2026-11-27T00:00:00Z",
  "plugins": [
    {
      "plugin_id": "context-compactor",
      "name": "上下文压缩器",
      "version": "1.0.0",
      "summary": "",
      "description": "",
      "author": { "name": "GuiQIHueas" },
      "source": "community",
      "capabilities": ["tool", "hook"],

      "like": 100,
      "downloadCount": 100
    }
  ]

```

- 支持分片：主文件给 `shards[]`（每片 URL + sha256），总线按需拉取合并。
- 内存缓存 10 分钟；拉取失败回退磁盘缓存并标记 `stale`，不把空目录当好数据覆盖。
- 写操作只接受同源 POST，请求体有大小上限；目录只读、不带凭据。

### 12.2 私有市场

- `HARNESS_PLUGIN_REGISTRY_URL` 配置甲方私有目录，可与公共目录并存或替代。
- 集成模式下可关闭公共市场（`HARNESS_PLUGIN_MARKET_ENABLED=false`），只展示白名单插件。
- 白名单之外的插件不展示、不可安装。

### 12.3 DSH 只读导入

- 新增 `src/plugin_bus/catalog_dsh.py`，只读适配 `awesome-dsh-plugin` 社区目录（npm 镜像优先、官方源兜底）。
- 字段映射：包名/版本/描述/仓库/作者 → 本地 manifest 摘要字段；`plugin_id` 由包名清洗。
- Cordis 插件不能直接运行，只做「转译导入」：能提取 SKILL 内容的按技能导入；其余条目标记 `unsupported`，**不伪装成可安装**。
- 导入结果只进目录展示，不自动安装。

## 14. 项目级插件

- 目录：`<project_root>/.commonharness/plugins/{plugin_id}/manifest.json` + 包内容。

- 一次性进程模式不支持跨调用保持内存状态，插件应把状态放 `host.storage` 或沙箱文件。
- 项目级插件不参与更新与版本回滚，随项目目录走。

1. Agent 在沙箱内生成插件包，补齐 `manifest.json`。
2. 在沙箱内执行 `initialize → describe → smoke`，产出可安装包与自测结果。
3. 需要现成插件时：调市场 API 检索 → 下载到沙箱 → 静态扫描 → 协议试运行 → 生成安全报告（能力、权限、越权行为）。
4. 安装必须经用户确认：Agent 只能通过快捷选项或 HITL 卡片提议，用户确认后才走正常安装通道，且只装到当前用户名下。
5. 涉及外部系统权限的集成插件，授权清单逐条确认，不能由 Agent 代为同意。
6. 使用效果进轨迹与经验库；效果不好时 Agent 提改进方案，产出新版本再走验证。

### 15.3 安全约束

- Agent 不直接写 `plugins/users/`，只能产出包交给安装接口。
- 自迭代产出的插件与社区插件走同一套四道闸门。
- 用户可配置是否允许 Agent 自动提议、是否允许直接本地安装（默认关闭直接安装）。

### 20.1 P0

## 21. 风险与边界

| 风险 | 说明 | 应对 |
| :-- | :-- | :-- |
| 子进程不是 OS 级隔离 | 宿主侧插件与宿主同权限 | 装前沙箱验证 + 运行时权限拦截；高风险只允许沙箱模式 |
| 多 worker | 进程注册表与连接池是进程内状态，PG 只存状态 | 固定单 worker，或后续把 Bus 收口到独立网关 |
| Windows 进程管理 | 子进程树、强杀、端口/句柄继承 | 启动时建独立进程组；shutdown 超时后强杀；记录 PID 与版本便于排障 |
| 沙箱一次性进程 | 无法跨调用保持内存状态 | 文档明确限制；状态走 `host.storage` 或沙箱文件 |
| 供应链 | 社区包来源不可控 | sha256 必填、静态扫描、沙箱试运行、来源展示 |
| UI 绕过 | iframe 或 postMessage 越权 | 无 `allow-same-origin`、CSP、消息白名单、只读路由 |
| 与 MCP 工具重名 | 注入冲突导致工具覆盖 | 统一前缀 + 启动期冲突检测 + 审计 |
| 市场目录不可信 | 远程目录被篡改 | 分片 sha256、HTTPS、失败回退本地缓存、空目录不覆盖 |

1. **stdio 用 `subprocess.Popen` + 读线程**，不用 `asyncio.create_subprocess_exec`。原因是项目在 Windows 上统一使用 Selector 事件循环（psycopg 要求），Selector 不支持 asyncio 子进程。对外行为与设计一致。
2. **`plugins-disabled` 目录暂未启用**：启停状态统一以 PG `plugin_user_state` 为准，内置与用户插件共用一套语义；目录保留给后续物理隔离。
3. **远程插件不支持反向 `host.*`**：HTTP 传输没有回调通道；远程插件只能通过配置与自身接口访问外部系统。
4. **沙箱一次性进程不支持反向 `host.*`**：一次性 stdio 会话无法与宿主往返，插件状态应放沙箱文件或安装时配置。
5. **市场目录**：P0 只读本地 `plugins/catalog/catalog.json`；P1 已补齐公共源、私有源、分片、stale 回退、白名单与 DSH 转译。

与设计不一致或需要后续补强：

1. **DSH 源默认不拉取**：`HARNESS_PLUGIN_DSH_CATALOG_URL` 为空即跳过，避免每次目录请求访问外网；配置 npm 搜索地址后才会合并 DSH 条目。
2. **DSH 条目一律 `installable=false`**：P1 只做转译展示，不自动把 Cordis 插件变成可运行插件；`skill-import` 也需要后续走技能安装通道。
3. **项目级插件不自动注入对话工具**：按确认口径只提供发现、沙箱一次性调用与命令系统查询入口，等第五章 `/plugin` 决定显式绑定。
4. **UI slot 目前只有 `chat.sidebar` 一个挂载点**：`console.plugin.detail`、`chat.composer.after` 先保留在 manifest 契约里，未挂载。
5. **目录分片只支持 JSON 文档**：分片内必须是数组或 `{plugins: []}`，不做压缩包；`sha256` 缺失时跳过校验但不阻断。
6. **前端安装进度卡与插件页共用轮询**：一键更新按“逐条等待 job 终态”顺序执行，失败不连坐。
7. **真实沙箱仍未端到端验证**：项目级插件与安装试运行都依赖 OpenSandbox；P1 冒烟使用 `HARNESS_PLUGIN_SANDBOX_VERIFY=false` 验证宿主 stdio 安装链路，沙箱链路需在可用环境补测。
8. **UI 静态资源的 `frame-ancestors` 跟随 `HARNESS_CORS_ORIGINS`**：默认放行本地 Vite 端口；Electron `file://` 场景若被浏览器策略拦截，需要把控制台来源补进该变量。
9. **`sys_plugins` 只支持 Python 进程内模块**：入口用文件路径加载，目录名或 `plugin_id` 可以含连字符；不支持 JS / C# 内置插件，这类仍走外部子进程或远程形态。打包时需要把 `src/plugin_bus/sys_plugins/` 作为数据目录一并收集，否则冻结后无法按路径读取。
10. **`sys_plugins` 与 `HARNESS_HOME/plugins/builtin` 合并时源码根优先**；内置插件不写 `plugin_install`，用户只能启停，不能卸载。

决策与边界：

1. **SDK 目录用 `csharp/` 而不是字面量 `C#`**：避免 `#` 在 URL、CLI 与构建缓存路径中的转义问题；对外仍称「C# SDK」。
2. **Python 不单列 SDK**：宿主是 Python，内置插件直接用 `handle(method, params)`，外部 Python 插件使用 `plugin-development` 的模板。
3. **SDK 本轮只交付调研与设计**：C# / TypeScript 接口草案、测试与发布方案已写入调研文档；代码、样例与 `docs/plugin_protocol.md` 留到下一步。
4. **内置插件 `text-toolkit` 只做纯文本工具**：不申请权限、不访问宿主文件与网络，作为 inprocess 插件的首个可用样例。
5. **SKILL 模板同时覆盖 stdio 与 inprocess**：内置与外部插件的差异落在 manifest 与入口，不改变协议语义。
