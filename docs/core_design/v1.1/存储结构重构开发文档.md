Author: GuiQIHueas  
Scope: 仅第四章的 MCP / SKILL；Plugin 本期不动

## 1. 背景与范围

第四章要解决的是"发布后多用户部署时，MCP 与 SKILL 的存储位置与索引方式"。本期只做两件事：

- 统一基准目录：新增 `PUBLISH_PROGRAM_PATH`，所有 MCP / SKILL 路径相对它推导。
- 把 SKILL / MCP 的"索引"统一成文件索引，不新增 PostgreSQL 表。

不做：Plugin 模块、MCP/插件密钥库、RAG 存储、前端页面改版。

## 2. 现状与问题

### 2.1 两套路径并存

- 打包模式 MCP 根：`USER_DATA_DIR/mcp`；源码模式：`PROJECT_ROOT/mcp`（`config.py::_mcp_root`）。
- 打包模式 MCP 运行态：`USER_DATA_DIR/.mcp`；源码模式：`PROJECT_ROOT/.mcp`（`config.py::mcp_workspace_root`）。
- 打包模式技能：`USER_DATA_DIR/skills`；源码模式直接写 `src/agent/skills`（`config.py::_resolve_skills_root`）。

### 2.2 用户隔离只做了一半

- MCP 配置：`USER_DATA_DIR/users/{uid}/mcp/servers.json`，已按用户隔离。
- MCP 运行态：`.mcp/users/{uid}/{server_id}/`，目录隔离了，但根仍在项目目录。
- 技能：`USER_DATA_DIR/users/{uid}/skills`，每个用户首次访问整目录复制一份内置技能。

### 2.3 技能库的三个具体问题

1. N 个用户复制 N 份内置技能，磁盘放大。
2. 内置技能升级后，用户目录里的旧副本不会刷新。
3. 沙箱预热同步的是全局 `SKILLS_ROOT`，不是用户技能库（`sandbox_manager.py::_create_reserve`），存在跨用户读到同一份技能视图的风险。

### 2.4 索引现状

- MCP：`servers.json` 本身承担索引职责，没有额外索引层。
- SKILL：每次列表都实时扫目录，没有缓存。
- 两者都没有 PG 表；PG 里只有档案 `mcp_server_ids`、任务流 schema、轨迹事件这类引用。

## 3. 目标设计

### 3.1 基准目录

```python
PUBLISH_PROGRAM_PATH = os.getenv("PUBLISH_PROGRAM_PATH") or ""   # 未设置即不启用

if PUBLISH_PROGRAM_PATH 已设置且可写:
    HARNESS_HOME = PUBLISH_PROGRAM_PATH
else:
    HARNESS_HOME = USER_DATA_DIR
```

- 未设置 `PUBLISH_PROGRAM_PATH`：完全沿用 `USER_DATA_DIR`，现有安装、测试、桌面环境行为不变。
- 设置后：部署目录（exe 所在目录或部署根）成为统一基准；不可写时整体回退 `USER_DATA_DIR`，布局不变。
- `HARNESS_MCP_ROOT`、`HARNESS_SKILLS_ROOT`、`HARNESS_MCP_WORKSPACE_ROOT` 保留为显式覆盖，优先级最高，仅用于调试。

### 3.2 目标布局

```text
<HARNESS_HOME>/
  mcp/
    servers.template.json             # 只读模板
    users/{uid}/servers.json
    users/{uid}/runtime/{server_id}/npm-cache/
    users/{uid}/runtime/{server_id}/logs/stdio.log
  skills/
    builtin/                          # 内置技能，只读
      main/{skill}/
      subagents/{agent}/{skill}/
    users/{uid}/
      main/{skill}/
      subagents/{agent}/{skill}/
      skills-disabled/                # 用户技能的停用区
      skills-state.json               # builtin 版本 + 用户停用的内置技能
  cache/
    index/
      skills-{uid}.json               # 可删，重建
      mcp-{uid}.json
  logs/
```

### 3.3 SKILL overlay

- `skills/builtin`：随发布更新，只读。
- `skills/users/{uid}`：只放用户自己创建的技能，以及用户改过的同名技能。
- 读取时先用户、后内置，同名以用户为准；不再把内置技能复制进用户目录。
- 内置技能按用户停用：写入 `skills-state.json` 的 `disabled_builtin` 列表，不移动内置文件。
- 用户技能停用：仍移动到 `skills-disabled/`，保持现有语义。

### 3.4 文件索引（不落库）

- 统一 `src/agent/file_index.py`，为 SKILL / MCP 提供内存 + 磁盘快照缓存。
- 缓存文件放 `cache/index/{module}-{uid}.json`，字段：`signature`、`built_at`、`entries`。
- `signature` 由根目录 mtime、`servers.json` mtime、`skills-state.json` mtime 组成；变化即重建。
- 安装、卸载、启停、导入后主动 `invalidate`。
- 索引失效或损坏时回退实时扫描，不影响主流程。

## 5. 迁移方案

迁移在应用启动时执行一次，并在用户首次访问时兜底执行。原则：只复制、不删除，保留旧数据可直接回滚。

1. MCP 配置：`USER_DATA_DIR/users/{uid}/mcp/servers.json` → `<HARNESS_HOME>/mcp/users/{uid}/servers.json`，目标已存在则跳过。
2. MCP 运行态：`PROJECT_ROOT/.mcp/users/{uid}/{server_id}` 与 `USER_DATA_DIR/.mcp/users/{uid}/{server_id}` → `<HARNESS_HOME>/mcp/users/{uid}/runtime/{server_id}`，目标存在则跳过。
3. 技能：`USER_DATA_DIR/users/{uid}/skills` → `<HARNESS_HOME>/skills/users/{uid}`。
4. 技能迁移时与 `skills/builtin` 做内容比对：目录内容完全一致的内置技能不复制，交给 overlay；有差异的才复制到用户目录。
5. 停用技能：与内置一致的，写入 `skills-state.json.disabled_builtin`；其余复制到 `skills-disabled/`。
6. 迁移完成写 `<HARNESS_HOME>/.storage-migration.json`，记录版本与时间；重复启动直接跳过。

## 6. 配额与清理

### 6.1 SKILL

- 默认 200 MB / 用户、2000 个文件，超限拒绝安装。
- 统计范围：`skills/users/{uid}`，不含 builtin。

### 6.2 MCP

- 单用户 npm 缓存默认 2 GB；超限按 server 目录 mtime 从旧到新删除。
- `stdio.log` 超过 5 MB 轮转，保留 `stdio.log.1`、`stdio.log.2`。
- 运行态目录超过 7 天未更新则删除（可重建，不备份）。

### 6.3 调度

- FastAPI lifespan 启动时跑一次，随后每 6 小时跑一次。
- 任务异常只记日志，不影响服务。

## 7. 兼容与回滚

- 未设置 `PUBLISH_PROGRAM_PATH` 时，`HARNESS_HOME = USER_DATA_DIR`，现有部署无需改配置。
- 迁移只复制不删除，回滚只需恢复旧版本程序并继续使用旧目录。
- 索引缓存可随时删除；删除后首次请求自动重建。
- `HARNESS_MCP_ROOT` / `HARNESS_SKILLS_ROOT` 仍是最高优先级覆盖，用于测试与特殊部署。

## 8. 验收

1. 未设置 `PUBLISH_PROGRAM_PATH`：启动后 MCP、技能仍能在 `USER_DATA_DIR` 下正常工作。
2. 设置 `PUBLISH_PROGRAM_PATH` 到可写临时目录：MCP 配置、运行态、技能全部落在该目录。
3. 设置到只读目录：自动回退 `USER_DATA_DIR` 并打印告警。
4. 旧数据迁移：构造旧目录后启动，数据出现在新位置，旧目录保留。
5. 技能 overlay：内置技能在列表中可见、可停用不可删；用户同名技能覆盖内置。
6. 索引：删除 `cache/index` 后首次列表重建；修改技能目录后索引失效并刷新。
7. 配额与清理：超限安装被拒绝；MCP 日志超限轮转；闲置运行态被清理。

## 9. 风险与后续

- 技能管理工具仍只操作用户目录，内置技能无法通过 Agent 工具删除，这是预期行为。
- 多 worker 部署下索引缓存与 MCP 连接池仍是进程内状态；多 worker 前需要固定单 worker 或收口 MCP 网关。
- 后续 P2：MCP/Plugin 密钥库、MCP LKG 缓存按用户隔离、Plugin 存储接入。
