---

## 1. 实验目的

设计文档里的分档函数是：

```
S = exp( Σ wi·ln(xi+ε) / Σ wi )
p_HD = σ(α(S-θ2)), p_MD = σ(α(S-θ1)) - σ(α(S-θ2)), p_EZ = 1 - σ(α(S-θ1))
```

需要回答四个问题：

1. 这套参数能不能从数据里恢复？边界会不会抖？
2. `α` 该取多大？太小和太大分别坏在哪？
3. 真实任务的复杂度分布是什么？边界该放在哪？
4. `τ`（低置信度阈值）和 `δ`（滞回宽度）取多少合适？

实验分两部分：**A 合成数据**验证参数可恢复性与数值行为；**B 真实数据集**给出基线参数与真实分布。

---

## 2. 实验 A：合成数据（验证可实现性）

### 2.1 设置

- 3000 条样本，7 维特征 `x ~ Beta(2,2)`，真权重 `[0.18, 0.12, 0.20, 0.14, 0.10, 0.10, 0.16]`；
- 由真权重算潜在复杂度，按 50% / 85% 分位生成三档，标签噪声 5%；
- 70/30 划分，Adam 拟合有序 logistic 的负对数似然。

### 2.2 结果

| 方案 | 测试准确率 | 说明 |
| :-- | :-- | :-- |
| 等权 + 硬阈值 | 83.89% | 边界网格搜索 |
| 专家权重 + 硬阈值 | 86.56% | 权重先验偏差较大 |
| 专家权重冻结 + 有序 logistic | 86.33% | `α=48.1`，只拟合边界 |
| 权重与边界全拟合 | **94.89%** | `α=59.7`，`θ=[0.4428, 0.5542]` |

权重恢复：拟合权重与真权重的 L1 距离 `0.0283`，专家先验的 L1 距离 `0.2000`。说明在模型设定正确时，有序 logistic 能恢复权重；**主要收益来自权重校准，不是平滑本身**。

### 2.3 `α` 的边界行为

`α` 不是越大越好，也不是越小越平滑。中间档要能被 argmax 选中，需要：

```
α · (θ2 - θ1) / 2 > ln(2)   =>   α > 2·ln(2) / (θ2 - θ1)
```

本次数据 `θ2-θ1=0.111`，理论下限 `α_min=12.45`。实测：

| `α` | 测试准确率 | 低置信度比例 | 说明 |
| :-- | :-- | :-- | :-- |
| 3 / 5 / 8 / 12 | 64.44% | 56.6%–91.3% | MD 永远赢不了 argmax，退化为二分类 |
| 16 | 83.56% | 51.6% | 刚过下限 |
| 20 | 91.56% | 48.9% | 可用 |
| 30 | **95.44%** | 22.8% | 最优 |
| 60 | 94.89% | 8.1% | 过陡，置信度信息几乎消失 |

**结论**：`α` 必须先满足下限，再按"边界抖动率"往上调；越过最优点后准确率下降、且低置信度样本被压没，`τ` 规则会失效。

### 2.4 抖动与滞回

对 `S` 加高斯扰动模拟重复评估，统计档位切换率：

| 噪声 `σ` | 无滞回 | `δ=0.02` | `δ=0.03` | `δ=0.05` |
| :-- | :-- | :-- | :-- | :-- |
| 0.01 | 4.75% | 0.13% | 0% | 0% |
| 0.02 | 10.13% | 1.50% | 0.50% | 0% |
| 0.04 | 19.00% | 11.00% | 8.13% | 2.00% |

滞回是必要的：`σ=0.02` 时把切换率从 10.1% 压到 0.5%（`δ=0.03`）。

### 2.5 低置信度升档

`α=59.7` 时模型非常自信，低置信度样本只占 8.1%，升档反而把准确率从 94.89% 拉到 91.89%，严重低估率本来就是 0。**升档规则在"模型已经很陡"时是纯损失**，只有在真实数据那种重叠严重、`α` 较小的场景才有价值（见实验 B）。

## 3. 实验 B：真实数据集

### 3.1 数据集

| 项 | 值 |
| :-- | :-- |
| 来源 | `regolo/brick-complexity-extractor`（HF） |
| 许可 | CC-BY-NC-4.0（仅研究/评估，不可商用） |
| 字段 | `text`、`label`（easy / medium / hard） |
| 规模 | train 65,307 / val 7,683 / test 3,841 |
| 类别先验 | easy 32.67% / medium 51.29% / hard 16.04% |
| 标签来源 | LLM judge（Qwen3.5-122B）一致性采样，非人工标注 |
| 已知问题 | 中/难边界主观，约 15% 边界样本存在分歧；仅英文 |

注意：最终发布文件里没有 README 提到的 `confidence` 字段，本实验按全量训练。

### 3.2 模型对比

TF-IDF：word 1–2 gram，`min_df=2`，`max_features=200k`，`sublinear_tf`。

| 模型 | 准确率 | Macro-F1 | easy 召回 | medium 召回 | hard 召回 | ECE |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 多数类 | 50.20% | 0.2228 | 0 | 100% | 0 | — |
| MultinomialNB | 64.18% | 0.5563 | 53.95% | 84.60% | 22.71% | 0.0868 |
| LogisticRegression | **68.76%** | **0.6542** | 67.94% | 76.19% | 47.79% | 0.0699 |
| LogisticRegression + balanced | 66.02% | 0.6463 | 72.01% | 62.55% | **64.51%** | 0.0480 |
| 仅文本统计特征 + LR | 50.17% | 0.2825 | 4.85% | 94.87% | 5.68% | 0.0217 |

读法：

- 文本统计特征（长度、词数、问号、从句标点等）几乎无效，macro-F1 只有 0.28。**复杂度不是"文本长短"**，必须有语义特征或模型。
- 默认 LR 的 hard 召回只有 47.8%；`balanced` 把 hard 召回提到 64.5%，代价是 medium 召回掉 13.6pp、整体准确率掉 2.7pp。
- 单靠 query 文本，macro-F1 上限大约 0.65。这是"入口只做一次文本判定"的能力上限，不能把它当唯一依据。

### 3.3 有序标定

把 LR 的概率压成一维分数 `S_text = (P(medium) + 2·P(hard)) / 2`，在验证集上拟合有序 logistic：

| 参数 | 拟合值 |
| :-- | :-- |
| `α` | **7.1719** |
| `θ1`（EZ/MD） | **0.2654** |
| `θ2`（MD/HD） | **0.7589** |
| 测试集准确率 | 68.71% |
| 测试集 Macro-F1 | 0.6446 |
| 严重低估率（真实 hard → EZ） | 3.94% |

对照：按训练先验分位对齐的边界是 `θ1=0.3087`（32.7% 分位）、`θ2=0.6472`（84.1% 分位）。拟合出的 `θ2` 更高（0.759，约 90% 分位），说明在标签噪声下，模型倾向于"只有很像 hard 才判 hard"，用召回换精度。

真实数据的 `α=7.17` 与合成数据的 `59.7` 差一个数量级：真实任务的特征重叠严重，过渡带本来就宽。**这直接说明合成实验里"平滑没带来收益"的结论不能外推**——真实数据上平滑和置信度是必要的。

### 3.4 `τ`（低置信度阈值）

在测试集上把 `max(p) < τ` 的样本升一档：

| `τ` | 低置信度比例 | 准确率变化 | 真实 hard 被判成 EZ 的比例 |
| :-- | :-- | :-- | :-- |
| 基线 | — | 68.76% | 6.31%（40/634） |
| 0.55 | 14.35% | −3.10pp | ≈3.6% |
| 0.60 | 22.47% | −5.29pp | ≈2.8% |
| 0.65 | 30.85% | −7.89pp | ≈2.2% |

结论：升档确实能减少严重低估，但代价是整体准确率。**`τ=0.55` 是平衡点**（−3.1pp 换掉 42% 的严重低估）；`0.60` 适合高安全场景；`0.65` 代价过大，不建议。

### 3.5 滞回宽度

对 `S_text` 加扰动，模拟同一任务重复评估：

| 噪声 `σ` | 无滞回 | `δ=0.02` | `δ=0.04` | `δ=0.06` |
| :-- | :-- | :-- | :-- | :-- |
| 0.01 | 1.07% | 0.03% | 0% | 0% |
| 0.02 | 2.27% | 0.52% | 0.05% | 0% |
| 0.04 | 4.63% | 2.34% | 0.94% | 0.42% |

`δ=0.02–0.04` 足够；噪声大时取 0.04。

## 4. 基线参数建议

| 参数 | 建议值 | 依据 |
| :-- | :-- | :-- |
| `θ1` | 自有 `S` 的 **32.7% 分位** | 训练集 easy 先验 |
| `θ2` | 自有 `S` 的 **84.0% 分位** | easy + medium 先验 |
| `α` | **7.2**，且必须 `> 2·ln2/(θ2-θ1)` | 真实数据拟合；下限是中间档可被选中的必要条件 |
| `τ` | **0.55**（平衡）/ **0.60**（保守） | 准确率与严重低估的权衡 |
| `δ` | **0.02–0.04** | `S ∈ [0,1]` 下的抖动抑制 |
| `wi` | 专家先验，暂不拟合 | 本数据集没有 7 维特征，无法直接拟合 |

### 4.1 为什么边界用分位而不是直接搬 `0.2654 / 0.7589`

`S_text` 是文本模型的输出分布，`S` 是 7 维特征的几何平均，两者量纲和分布都不同。直接搬绝对值会系统性错档。正确做法是：**先在自己的 `S` 上跑一批历史任务，按类别先验取分位点**，再固定边界。

### 4.2 为什么不能从这份数据拟合 7 维权重

数据集只有 `text` 和 `label`，没有 `complexity / uncertainty / impact / scale / dep_depth / tool_diversity / acceptance` 七维特征。TF-IDF 的系数是词权重，不是维度权重。要拟合 `wi`，必须在调度器自己的执行记录里采集这 7 维，这正是设计文档 §1.5 主动学习要做的事。

### 4.3 文本分类结果的正确用法

- 可以作为一个**额外信号**参与 `x` 的计算（例如把 `P(hard)` 作为 `uncertainty` 或 `scale` 的辅助项），但不能当唯一入口；
- hard 召回 47.8%（默认）/ 64.5%（balanced）意味着单靠它至少漏掉三分之一的高难任务；
- 数据集是 LLM 标签 + 非商用许可，只能作为离线先验，不要直接进生产链路。

---

## 5. 对设计文档的修正

1. `α` 的初值从"5–10"收窄为 **7.2**，并补充下限约束 `α > 2·ln2/(θ2-θ1)`；实验 A 已经证明低于下限时 MD 类完全不可选。
2. `τ` 从 0.60 调整为 **0.55 默认**，因为真实数据上升一档的准确率代价约 3pp；高安全场景再切 0.60。
3. `δ` 明确为 **0.02–0.04**，不再留空。
4. 增加一条工程约束：**边界必须按自有 `S` 的分位数标定**，不能跨特征空间复制。

## 7. 局限

- 数据集标签是 LLM judge 产物，存在系统性偏差，不是人工金标准；
- 只有英文 query，无法代表中文任务分布；
- `S_text` 与调度器的 7 维 `S` 不是同一空间，本报告的边界只能作为分位对齐的依据，不能直接当常量；
- 抖动实验是加高斯扰动的模拟，不是真实重复评估；上线后应改用同一任务多次评估的实际方差来校准 `δ`。
