## 一、范围与边界

### 1.1 v1 交付范围

|:--|:--|
| 编译期 | 结构解析、数据校验（安全 + 结构）、流编译器（schema→执行计划）、流程索引器 |
| 运行期 | 流程路由器（检索 + LLM 终选 + fallback）、执行器（步骤状态机、checkpoint 校验回退、fork-join、SubAgent 委派、中途接管） |

### 1.2 v1 明确不做

- 条件分支（需要时拆多条流或走通用 Agent 循环）
- 子流嵌套层级 > 2
- 步骤级 MCP 覆盖（只有流级配置）
- HITL 配置项（Agent 自动判断 + 系统级强制审批走现有契约）
- 评估指标看板（v1 只落数据）
- 多租户

## 三、数据模型与存储

### 3.1 核心模型（`models.py`）

与设计文档 3.1/3.2 一致，用 pydantic 定义：`TaskFlow`、`Step`、`Subflow`、`ExecutionPlan`、`ExecutionUnit`（`step` / `fork`）、`Execution`、`StepTrace`。关键字段：

- `TaskFlow.source`: `builtin | user`；`status`: `draft | published`
- `Step.skills`: `"auto"` 或技能名数组；`Step.executor`: `"main" | "auto" | "subagent:<role>"`
- `Step.checkpoint`: bool；`Step.example`: 可选参考样例（校验对照基准）
- `ExecutionPlan.schema_hash`：与 schema 绑定，schema 变更必须重编译
- `Execution.entry_step`：中途接管入口；注入状态标记 `user_provided`

### 3.2 PostgreSQL 表（`store.py` 建表）

```sql
CREATE TABLE IF NOT EXISTS task_flow (
    id            TEXT PRIMARY KEY,            -- tf_<ulid>
    user_id       TEXT NOT NULL,               -- 用户隔离；内置流为 '__builtin__'
    name          TEXT NOT NULL,
    status        TEXT NOT NULL,               -- draft | published
    source        TEXT NOT NULL,               -- builtin | user
    schema        JSONB NOT NULL,              -- TaskFlow schema v1
    plan          JSONB,                       -- 执行计划；draft 未发布可为空
    schema_hash   TEXT,
    search_doc    JSONB,                       -- 索引器产出的可检索描述
    embedding     VECTOR,                      -- 若库有 pgvector 则启用，否则降级关键词召回
    created_at    TIMESTAMPTZ DEFAULT now(),
    updated_at    TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_task_flow_user ON task_flow(user_id, status, updated_at DESC);

CREATE TABLE IF NOT EXISTS task_flow_execution (
    id            TEXT PRIMARY KEY,            -- ex_<ulid>
    flow_id       TEXT NOT NULL REFERENCES task_flow(id),
    user_id       TEXT NOT NULL,
    thread_id     TEXT NOT NULL,               -- 关联会话
    schema_hash   TEXT NOT NULL,
    entry_step    TEXT,                        -- 中途接管入口步骤
    status        TEXT NOT NULL,               -- running | done | failed | aborted
    step_traces   JSONB NOT NULL,              -- StepTrace[]
    trace_id      TEXT,                        -- Langfuse / LangSmith
    created_at    TIMESTAMPTZ DEFAULT now(),
    finished_at   TIMESTAMPTZ
);
CREATE INDEX IF NOT EXISTS idx_execution_flow ON task_flow_execution(flow_id, created_at DESC);
```

### 3.3 内置流加载（`builtin/loader.py`）

- 启动时扫 `src/task_flow/builtin/*.json` → 过同一套 `validators` → 写入 `task_flow` 表（`user_id='__builtin__'`，`source='builtin'`），已存在则按 `schema_hash` 判断是否更新。
- 校验失败：记 warning 日志并跳过该文件，**不阻断启动**。
- 用户"复制为我的任务流"：拷贝 schema，`source='user'`、`status='draft'`、生成新 id。

## 四、编译期实现

四段管线纯程序逻辑、不调用 LLM，保存/发布时同步触发。入口：

```python
# src/task_flow/__init__.py
def compile_flow(ui_payload: dict) -> tuple[TaskFlow, ExecutionPlan, dict]:
    flow = parser.parse(ui_payload)                 # ①
    validators.run_all(flow)                        # ② 失败抛 FlowValidationError(逐条错误)
    plan = compiler.compile(flow)                   # ③
    search_doc = indexer.build_search_doc(flow)     # ④
    return flow, plan, search_doc
```

### 4.1 ① 结构解析器（`parser.py`）

UI JSON → `TaskFlow` pydantic 模型。只做结构映射与默认值填充（`skills` 缺省 `"auto"`、`executor` 缺省 `"auto"`、`checkpoint` 缺省 `false`），不判断语义。pydantic 校验错误直接作为"结构不可读"返回。

### 4.2 ② 数据校验器（`validators/`）

每个 Pass 是 `(flow: TaskFlow, ctx: ValidationContext) -> list[FlowIssue]`，`ValidatorRegistry` 支持开关与单测。`FlowIssue` 携带 `step_id` 便于前端就地标注。

| Pass | 规则 | 实现要点 |
|:--|:--|:--|
| safety.injection | 提示注入模式 | 模式库（正则 + 关键词组）匹配 `instruction` / `constraints` / `example` / `trigger_examples`；模式库独立成 JSON 便于维护 |
| safety.dangerous | 危险指令 | 破坏性指令词表（删除数据、格式化、关停服务等） |
| safety.privilege | 越权诱导 | 访问他人数据、泄露密钥、绕过权限等表述 |
| structure.steps | 步骤合法 | 非空、id/名称唯一 |
| structure.refs | 引用存在 | `skills`（查 `find_skill_directory`）、`executor` 角色（查 `subagents/configs/*.yaml`）、`mcp_services`（查 MCP 注册表）均存在；`auto` 跳过 |
| structure.parallel | 并行合法 | 分支数量不限（至少 1 条）、每分支 ≥ 1 步、嵌套 ≤ 2 层 |
| structure.length | 字段长度 | 名称/指令/示例超阈值拒绝（阈值进 `agent/config.py`，默认如名称 50 / 指令 2000 / 示例 4000 字符） |
| structure.acyclic | 无环性 | v1 子流内联天然无环，留 Pass 占位 |

### 4.3 ③ 流编译器（`compiler.py`）

纯函数：拉平步骤为 `ExecutionUnit[]`，fork 单元内联分支步骤引用，计算 `schema_hash = sha256(canonical_json(schema))`。同输入必同输出，直接表驱动单测。

### 4.4 ④ 流程索引器（`indexer.py`）

产出 `search_doc = {name, description, trigger_examples, step_summary}`，并在发布时计算 embedding（复用 RAG 模块的嵌入模型配置）。召回与索引分离：召回逻辑在路由器。

## 五、运行期实现

### 5.1 流程路由器（`router.py`）

```python
async def route(message: str, user_id: str, ctx: HarnessContext) -> RouteDecision:
    # RouteDecision = Hit(flow, plan, entry_step=None)
    #               | TakeoverHit(flow, plan, entry_step="s3", user_state=...)
    #               | Miss()   → 走通用 Agent 循环
    #               | Suggest(candidates)  → 建议新建/选择
```

- **召回**：embedding 相似度 + 关键词，对 `search_doc` 取 top-3；无 pgvector 时降级纯关键词。
- **终选**：低成本模型判断候选是否适用（二分类 + 理由）。
- **显式指定**：消息中 @流名 或请求参数 `flow_id` 优先于检索。
- **中途接管**：消息含"我已经做了…/从第 N 步继续"时，模型对齐入口步骤，**生成待确认项返回前端，用户确认后才执行**（SSE 发 `takeover_confirm` 事件）。
- **未命中兜底**：走通用循环；任务完成后主 Agent 可发"保存为任务流"提示（前端跳转新建页预填草稿）。

### 5.2 执行器（`executor.py`）

执行器是 agent 图内的子图节点，按执行单元数组推进：

```
pending → running → checking(仅 checkpoint) → done
              │           │
              └──→ retrying(≤2) → degraded(主 Agent 兜底) → failed(上报)
```

- **步骤上下文最小化**：只注入当前步 `instruction + constraints + example + 上游状态摘要`。
- **checkpoint 校验**：规则检查或轻量模型评审；有 `example` 时以示例为对照基准；不合格带校验反馈重试 ≤2 次 → 主 Agent 兜底 → 仍失败 `failed` 上报，不静默跳过。
- **fork-join**：每条分支默认 `aload_subagent` 委派 SubAgent 并行执行，并发上限 4（配置项）；`join=all` 全部分支完成后各分支**摘要**注入下一单元上游状态；分支失败走同一回退策略，最终失败则 fork 失败。
- **中途接管**：从 `entry_step` 启动，用户产出注入为上游状态并标记 `user_provided`；入口前 checkpoint 不补做；可选轻量评审提示不阻断。
- **运行时安全**：工具参数白名单、SQL 只读、单步超时、总步数上限、SubAgent 内部循环检测。
- **HITL**：不加配置项，工具调用的中断走 `src/agent/hitl.py` 现有契约。

### 5.3 执行记录

每单元完成即 append `StepTrace`（输入/输出/耗时/校验结果/重试次数/状态来源），执行结束写 `task_flow_execution` 并关联 `trace_id`。SSE 向前端推送步骤进度事件驱动执行卡片。

## 六、API 契约（`src/api/task_flow.py`）

| 方法 | 路径 | 说明 |
|:--|:--|:--|
| GET | `/task-flows?page=&size=` | 分页列表（内置 + 我的，按更新时间倒序），返回卡片数据（含简图结构） |
| POST | `/task-flows` | 新建（draft），保存即跑解析+校验，返回逐条 `FlowIssue` |
| GET | `/task-flows/{id}` | 详情（schema + plan 状态） |
| PUT | `/task-flows/{id}` | 编辑；已发布流生成新 draft，不动在用 plan |
| DELETE | `/task-flows/{id}` | 删除（内置流 403） |
| POST | `/task-flows/{id}/publish` | 重校验 + 编译 + 建索引，绑定 `schema_hash` |
| POST | `/task-flows/{id}/fork` | 复制为我的任务流（内置流转可编辑） |
| GET | `/task-flows/{id}/executions` | 执行记录列表 |
| GET | `/executions/{ex_id}` | 执行详情（StepTrace 回放） |
| POST | `/chat` 扩展参数 `flow_id`、`entry_step`、`user_state` | 显式指定流 / 中途接管确认 |

错误约定：校验失败 422，body 为 `FlowIssue[]`（含 `step_id`、`pass`、`message`），前端就地标注。

## 八、开发顺序

| 阶段 | 内容 | 验收 |
|:--|:--|:--|
| P1 编译期 | models / parser / validators / compiler / indexer + 单测 | 保存一条流能出 plan 和 search_doc；坏输入逐条报错 |
| P2 存储 + API | store.py 建表、CRUD/发布/fork 端点 | Postman 走通全流程 |
| P3 运行期串行 | router（先关键词召回）+ executor 线性执行 + Execution 落库 + SSE 进度 | Chat 里命中一条纯线性流跑完，前端有执行卡片 |
| P4 并行与接管 | fork-join + SubAgent 委派 + 中途接管 | 并行流正确汇合；从 s2 接管能续跑 |
| P5 前端页面 | 列表页 + 详情页 + 改名 + 422 标注 | 可视化建流、发布、跑流、看回放 |
| P6 内置流 | loader + 1 条示例内置流 | 启动加载、只读、可复制 |

P1–P3 是最小闭环，先跑通再上加法。
