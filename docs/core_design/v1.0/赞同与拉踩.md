# 赞同与拉踩功能

Time: 2026/11/8

----

在人类社会中，赞同源自灵魂之间的共鸣、拉踩则反之，是观点上的不一。

用户可以对AI的回复进行赞同或拉踩，从而让智能体更加的了解用户的喜好、性格等，称之为AI与人的灵魂的"共鸣"。

在UI界面中，针对AI的每一次回复消息，用户都可以进行赞同或拉踩操作。

慧染用户可以通过发送自然语言来表达自己的想法，从而让AI体更加的了解用户的喜好、性格等。

不过一个简单的按钮，背后也可以隐含着不少的信息。

## 赞同

用户对AI的回复进行点赞，这通常可以表示用户对AI的回复表示同意或喜欢，或者说和用户的观点一致，又或者是简单的表示为我就想要你这样的回复，之后也保持这样的风格。

这种点一下按钮的操作，可以类比为，人类交流之间的肢体动作。一个人赞同另一个人的想法或者观点，除了言语表达之外，那就是肢体动作和表情了吧？

在目前的系统来看，表情交流很难实现。但是肢体动作可以实现一些简单的部分。

通常，用户点赞的行为出现，可以从一下这几个行为推理出来
- 喜欢这个AI的回复
    - 比如用户对AI回复的语言组织、语言风格、回复性格特色、又或者回复本身的内容等喜欢。
- 与用户的观点一致
    - 这个一般涉及到用户的观点、情绪、当时的情感等。
    - 这些情况通常是离散出现、随时间变化的，智能体应在日积月累的数据积累中，逐渐【记住】用户的观点、情绪、当时的情感。就像两个人互相交流，随着时间的推移，Agent会变得更加得接近用户得灵魂。
- 我想要你这样的回复，之后也保持这样的风格
    - 比如AI某次回答用到了一些好的比喻、又或者是讲解事情时，讲的很清楚、很详细；又或者是回复风格幽默风趣等等。
- 达到了用户灵魂深处的共鸣

值得一提的是，这些情况单看的话，都十分的正确，但是AI如何判断用户得点赞行为，其实还是需要根据上下文进行简单的推理。

通常可以认为，用户在点赞时，让Agent内部对用户透明的进行一次分析。比如根据上下文、用户偏好等等，来判断这一次得点赞行为是怎样的。

### 赞同行为的内部判别

点赞只是一个比特的信息，单凭它本身无法区分"喜欢风格""认同观点""想要复现"还是"灵魂共鸣"。因此 Agent 在收到赞同信号时，需要结合上下文做一次内部分析，把这一次点赞归入（或同时归入）以下几类，并分别落到不同的记忆层：

| 判别维度 | 观察依据 | 落点 |
| --- | --- | --- |
| 内容认同 | 用户此前的表述、立场、情绪倾向与回复是否一致 | 观点/立场记忆，用于后续对话中的立场对齐 |
| 风格偏好 | 回复的语言组织、幽默度、详略程度、比喻手法等 | 风格偏好记忆，用于后续回复的风格复现 |
| 表达诉求 | 回复是否恰好解决了用户当下的问题、是否"正是我想要的" | 场景—回复模式记忆，用于相似场景下的复用 |
| 深层共鸣 | 多轮上下文叠加、用户历史偏好与本次回复高度契合 | 长期画像，权重更高、衰减更慢 |

判别结果不需要向用户显式展示，Agent 在内部完成归因即可；若多次点赞指向同一维度，则该维度的偏好权重应被加强，并在后续回复中更稳定地体现出来。

## 拉踩

与赞同相对，拉踩表示用户对AI的回复不满意、不认同，或是认为回复偏离了自己的需求。它同样是灵魂之间的对话——只不过这一次是"观点上的不一"，是分歧被明确地表达了出来。

拉踩的价值不在于"惩罚"，而在于**纠偏**：它告诉Agent"这条路不对"，从而缩小下一次尝试的搜索空间。用户愿意拉踩，本身就说明用户还在意这段对话、还愿意给Agent修正的机会，这一点在设计中应当被珍视。

通常，用户拉踩的行为出现，可以从以下几个行为推理出来：

- **不认同回复的内容或观点**
    - 比如回复的事实有误、逻辑有漏洞，或者立场与用户相悖。
    - 这类拉踩应重点修正知识准确性与立场对齐，而非风格。
- **不喜欢回复的风格或表达方式**
    - 比如过于冗长、过于机械、语气不合、答非所问。
    - 这类拉踩应落到风格偏好记忆中，作为负向样本，降低类似表达的复现概率。
- **回复没有解决用户的问题**
    - 比如理解错了意图、答得太浅、没有给出可执行的方案。
    - 这类拉踩应关联到"意图理解"与"回答深度"两个维度。
- **触发了用户的反感或不适**
    - 比如措辞冒犯、越界、过度揣测。
    - 这类拉踩优先级最高，应作为强负向信号处理，并在后续对话中严格规避。

同样地，拉踩也需要结合上下文做内部判别：用户是对"这一条回复"不满，还是对"这一类回复"不满？是一次偶发的情绪表达，还是稳定的偏好信号？Agent 应在内部完成归因，避免因一次误判而过度修正、矫枉过正。

### 赞同与拉踩的对照

| | 赞同 | 拉踩 |
| --- | --- | --- |
| 语义 | 灵魂共鸣、观点一致 | 观点不一、需求未满足 |
| 作用 | 强化偏好，鼓励复现 | 纠偏，缩小尝试范围 |
| 记忆方式 | 正向样本，提升权重 | 负向样本，降低权重或标注规避 |
| 风险 | 过度迎合、风格固化 | 过度修正、变得畏缩 |
| 处理原则 | 归因到具体维度，避免笼统强化 | 区分偶发与稳定，避免一次否定全盘 |

两者都需要注意同一个问题：**单次信号的权重不应过高**。人的喜好是流动的、离散出现的，Agent 应在日积月累的数据中逐渐逼近用户的灵魂，而不是被某一次点击牵着走。

## 重新回答

"重新回答"是介于赞同与拉踩之间的一种特殊反馈：用户既没有明确否定，也没有表示满意，而是用行动说"再来一次"。

它隐含的信息通常有两层：一是**这次回复没有达到预期**，二是**用户仍愿意继续对话**。因此"重新回答"可以视为一次温和的负向信号，其权重应低于拉踩，但高于"无反馈"。

对 Agent 而言，"重新回答"最有价值的地方在于**对比**：同一次提问下的两次回复，一次被重新生成、一次被保留（或被赞同），这组对照本身就是极好的偏好数据。Agent 可以据此推断用户更倾向哪一种表达方式、详略程度或切入角度，并把它沉淀到风格偏好记忆中。

同时也要防止滥用式修正：如果用户频繁点击"重新回答"却始终不给出明确态度，Agent 不应无限地随机重试，而应在若干次之后主动询问用户"希望我在哪方面调整"，把隐式信号转化为显式表达——这也是"慧染用户可以通过发送自然语言来表达自己的想法"这一设计的用武之地。

## 小结

赞同、拉踩与重新回答，三个按钮背后是同一条主线：**让 Agent 在日积月累中更接近用户的灵魂**。

- 赞同是共鸣的回声，告诉 Agent"就是这样，继续"；
- 拉踩是分歧的表达，告诉 Agent"不是这样，改"；
- 重新回答是温和的催促，告诉 Agent"再试一次，但别原地踏步"。

每一个信号都不应被孤立地解读，而应结合上下文、结合用户的历史偏好、结合时间的积累去做归因。按钮只是入口，真正的功夫在按钮之后的推理与记忆之中。当这些离散的、随时间变化的信号被一点点沉淀下来，Agent 与用户之间的"共鸣"才会从一次点击，变成一种默契。
