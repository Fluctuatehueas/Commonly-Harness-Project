# 本文介绍 Agent 自我迭代优化机制

机制描述：  
Agent 从一次失败里提炼出规矩，总结出经验，下次遇到同类情况不再犯同样的错误。

Time: 2026/11/3
---

Agent在生产环境中一定需要自我迭代和自优化机制。我想到了可以从如下角度来进行设计  
## 一、Agent调度策略层，采用RL（强化学习）影响Agent的行为
- 从工具调用方面看，应对Agent调用工具的成功率、耗时、频次等角度，来进行一套奖励机制，从而让Agent拥有大量工具时，可以有一定的偏好。不过这一定有缺点，比如有一个工具是很关键的，但是由于环境问题导致此时不可调用或者调用失败，那此时如果进行奖励和惩罚，就会导致某些好用的工具变得不常用，不过这部分影响凭直觉上应该不会很大，需要有一套动态的奖惩策略。
    - 奖励不能只看“成功/失败”，要区分工具不可用（infra error） 与工具返回错误（tool error） 与工具正确但任务未完成。前者不应计入工具惩罚。
    - 用成功率的分母归一化（按调用次数而非总任务数），并对低频工具设置置信区间下限，避免“调了 2 次失败 1 次就被永久打入冷宫”。
    - 你提到的“动态奖惩策略”是对的，但需要具体化：对新工具/低频工具给探索预算，对高频工具才做稳定偏好更新。
- 支持Agent反思式的，自然语言驱动的强化学习。也就是说，Agent可以给自己记笔记、总结经验，分析错误点然后计入到Agent的记忆系统中（对用户透明）,Agent个人拥有该份【错题本】，从而增强了Agent的自我学习能力。
    - 但“直接计入记忆系统”需要加两个机制，否则会越学越贵、越学越偏：经验必须带效用评分（注入后是否真的改善了后续结果），无效经验要衰减剪枝；错题本不能无限膨胀，需要语义去重 + 定期压缩。
## 二、自我裁定机制
Agent 需要在关键节点上对自己“是否真的做对了”进行判定，但判定不能只依赖模型自己问自己。同一个模型既生成答案又验证答案，容易产生“自信的错误”——它能发现格式不符、明显矛盾这类表层问题，但对深层的事实错误、数值偏差、逻辑漏洞往往无法自查出来。因此，自我裁定应当设计为两层验证结构，并按任务风险分级触发。

### 第一层：LLM 自我反思（低成本初筛）
Agent 在输出前或执行下一步前，对当前结果做一次结构化自检，典型问题包括：
- 结果是否完整回答了用户的问题？
- 关键前提是否来自用户输入或已验证的工具返回，而非模型自行假设？
- 是否存在内部矛盾、格式错误、遗漏的必填项？
- 数值、日期、单位是否需要二次核对？

这一层的定位是初筛：低成本、可普遍启用，用于拦截明显的表层错误。但它不能作为准确性的最终保证，其结论只用于决定“是否需要进入第二层”。

### 第二层：外部验证器（准确性兜底）
对可验证的任务，引入模型之外的确定性校验手段，包括但不限于：
- 代码/脚本执行：计算类任务直接运行并比对结果；
- 测试用例与 schema 校验：结构化输出按预定义 schema 校验，代码类任务跑单元测试；
- 工具二次确认：对关键外部调用（查询、写入、提交）做一次独立复核或幂等重查；
- 数值范围与业务规则检查：统计结果、金额、日期区间等按业务规则做确定性断言。
- 数值范围与业务规则检查：统计结果、金额、日期区间等按业务规则做确定性断言。

第二层的结论优先于第一层：当外部验证器判定失败时，无论 LLM 自检是否“感觉对了”，都应触发修正或转人工，而不是继续执行。
## 三、从Harness工程层面看
> 参考QCon 全球软件开发大会·2026上海站 会议提纲  

轨迹绝对是一个可以大力开采的矿产资源。这就是最真实的Agent的干过的事的记录，也是Agent自己的直接的记忆记录。因此这份真实性与事实性，是绝对可以作为Agent自我迭代，就像人一样从历史经历感悟新的知识一样，最直接的路径。

### 1. Agent Trajectory Data Protocol（ATDP）：将传统日志（轨迹）升级为包含观测、隐状态、动作、结果、奖励和元数据的学习轨迹。  

ATDP的Schema定义是整个方案的数据基础。AReaL 2.0将每一步记录为六元组：
eₜ = ⟨oₜ, hₜ, aₜ, yₜ, rₜ, mₜ⟩
|字段|含义|实施要点|
|:--:|:--:|:--:|
|oₜ|可观测状态|	工具输出、检索结果、用户消息|	保留原始内容的脱敏后版本|
|hₜ| 隐含内部状态|规划草稿、推理摘要、置信度|不强制存储完整CoT，只保留决策相关结构，避免隐私负担|
|aₜ| 选择的动作|	工具调用（含类型化参数）、生成的token|	工具名+参数Schema+权限范围，不能只存工具名|
|yₜ| 动作结果|	工具返回值、用户接受/编辑/删除|	区分“返回了”和“被信任/忽略/纠正”|
|rₜ| 奖励信号|	二元结果、标量分数、自然语言评价|	延迟奖励一等公民：下一轮纠正、后续测试失败、重开的工单都可回填|
|mₜ| 元数据|	延迟、token数、成本、租户、Harness版本、工具Schema版本、检索索引快照、模型checkpoint|	没有版本化快照，轨迹只有统计价值，没有可重现性|

**应注意的点**:ATDP的核心工程价值在于回答“哪次检索、哪个工具调用、哪条记忆项导致了成败”，而不是追求字段全集。

### 2. Agentic Data Proxy：解决 Agent 交互中的轨迹采集、脱敏、持久化和回放问题。
Data Proxy的定位不是API网关、不是tracing工具、不是日志服务，而是把生产流量转化为有治理的学习素材的核心机制。它必须坐在Agent与以下所有组件之间：LLM推理后端、工具层、记忆系统、人类反馈通道。

四个必须实现的治理能力：

（1）脱敏（Redaction）——训练资格的前置条件
第一版最小闭环至少覆盖：API key、Bearer token、常见secret字段、邮箱、手机号。脱敏后仍保留 executionId 类关联标识，方便有权限用户回看原始轨迹。Data Proxy的核心设计要求是数据进入训练队列前即完成治理，而不是事后补救。

（2）权限与租户隔离
多租户场景下，聚合与隔离必须共存。一个编码Agent可以从跨团队的issue解决轨迹中获益，但不能暴露或学习许可边界之外的仓库内容。租户元数据不是合规装饰，它直接影响一次更新是否对目标群体有效。

（3）回放分级——区分“监控”与“学习”
监控系统问“发生了什么”，学习系统还必须问“如果换一个模型、提示、记忆项、检索策略或工具Schema，这次会成功吗？ ” 因此每条轨迹应标记为确定可回放 / 近似可回放 / 不可回放三档。确定可回放需要快照级的环境版本绑定；近似可回放允许mock依赖+固定seed；不可回放的轨迹仅用于统计，不进入反事实评估。

（4）奖励收割（Reward Harvesting）
Data Proxy负责捕获弱信号和延迟奖励：用户下一轮纠正、测试用例后置失败、人工标注回填、工单重开。这些信号必须在ATDP的 rₜ 字段中回填到已有轨迹，而不是作为新日志孤立存储。

### 3. Agent Evolution Control Plane：根据轨迹统计决定优化对象，例如 Memory 更新、Harness 调整或模型权重更新，并设置评估与回滚机制。

Control Plane要回答的不是“怎么训练”，而是“这次失败应该改哪一层，以及改完怎么验证” 。AReaL 2.0论文将Agent建模为一个复合策略，干预面包括：模型权重、Harness（Prompt/上下文策略）、Memory、工具Schema/路由、回滚、No-op。把所有反复出现的失败都当成微调问题，是生产中代价最高、且经常改错层的做法。

失败 → 干预面的归因映射（可直接作为每一个Agent运转的的初始逻辑）：

|轨迹信号|	优先干预面|
|:--:|:--:|
|狭窄、反复出现的知识缺失|	Memory 写入/更新|
|重复的流程性失败|	Skill / Harness（提示、编排、guardrail措辞）|
|工具路由错误或参数格式错误|	工具描述 / Schema / Router|
|失败横跨多个租户、任务和工具配置|	策略模型权重（RL/偏好优化）|
|金丝雀评估出现回归或不安全delta|	回滚|
|证据不足|	No-op|
|自动触发信号（替代人工巡检）|评估器得分、用户纠正率、工具失败簇、每次成功任务成本、金丝雀delta、分布漂移|
实施时可以先从规则引擎起步，用上述映射做第一版决策，随着轨迹量积累再引入统计显著性门槛。

每一次干预必须走完整的晋升阶梯，缺一不可：
```text
回顾性回放 → 离线回归测试 → Shadow评估 → 金丝雀发布 → 差分监控 → 版本化回滚
其中回滚不是“撤销代码” 。如果回滚的是模型权重，已经用旧权重执行并写入数据的运行不会被代码回滚撤销。因此版本化追踪必须覆盖“变更 → 执行 → 写入数据”的完整影响半径，回滚时要明确哪些在途任务需要人工核对。
```

先用Data Proxy把“能学的数据”治理出来，然后再进行ATDP采集，最后用 Control Plane 决定‘这次该学什么、改哪一层’，再交由对应干预面执行更新，并走完晋升与回滚阶梯。



## 四、深层的迭代方案

🗃️ 补充点一：经验本身需要“生命周期”，而非只被“写入”
你的文档里，反思结果和错题本被“计入记忆系统”，但没有说经验什么时候该被淘汰。这是自演进Agent最容易被低估的问题：被动累积（passive accumulation）——把记忆当作只增不减的静态档案，最终导致上下文污染和决策退化。

已有框架给出了可操作的生命周期机制：

ReMe 将记忆管理拆为三个机制：多面蒸馏（区分成功模式、失败触发条件和对比洞察）、场景感知复用（按情境检索而非全局注入）、基于效用的精炼（自动加入经验证的新记忆，剪除过时记忆）。它的一个关键发现是：Qwen3-8B配合ReMe，表现超过了没有记忆机制的Qwen3-14B——说明“管理得好的经验”可以部分替代更大的模型参数。

Darwinian Memory 更进一步，把记忆当作一个“适者生存的生态系统”：轨迹被分解为独立可复用单元，通过效用驱动的自然选择追踪生存价值，主动剪除次优路径、抑制高风险计划。在GUI基准上，它在零训练成本下实现了18.0%的成功率提升和33.9%的执行稳定性提升。

RoMeRL 则揭示了一个你可能没意识到的陷阱：memory-reward trap。当轨迹级奖励被联合分配给共同检索到的多条记忆时，无关经验可能获得误导性的效用更新，持续污染记忆库。它通过“降阶效用状态”将反馈集中到有界支撑集上，将维护的记忆规模减少了84.4%，同时把LLM调用减少了21.1%。

对你的文档意味着什么：在“错题本”和“经验记忆”之后，需要补一段经验淘汰规则——至少包括：效用评分（注入后是否改善后续结果）、时效衰减、语义去重、以及“低效用/过时经验”的剪枝或归档策略。否则你的“错题本”会从资产变成负债。

🔍 补充点二：反思本身需要被“元评估”，否则会系统性归因错误
你的第二部分已经引入了外部验证器，这是正确的。但有一个更深层的问题没有被触及：Agent的自我反思存在系统性的归因偏差。

研究发现了一种Actor-Observer Asymmetry（行动者-观察者不对称） ：当Agent作为“行动者”反思自己的失败时，倾向于把原因归于外部因素；而当它作为“观察者”审计他人时，则倾向于归因于内部故障。仅仅交换视角，就能在大多数模型上触发超过20%的归因翻转。

这意味着：即使你让Agent“认真反思”，它提炼出的“经验”也可能是错误的因果归因——把工具问题记成自己的问题，或把自己的规划错误记成环境问题。基于错误归因蒸馏出的“错题本”，会毒化后续决策。

对你的文档意味着什么：在第二部分“自我裁定”之后，可以考虑补一个反思的元评估机制。一个轻量的做法是：对关键失败，让Agent分别以“行动者”和“观察者”两种视角各做一次归因，如果两次归因不一致，则标记为高不确定性，不自动写入长期经验，转由外部验证器或人工仲裁。这与你的两层验证结构是兼容的，只是把验证对象从“结果对不对”扩展到“归因对不对”。

🛡️ 补充点三：自演进系统需要“免疫机制”，而非只靠输入过滤
你的Data Proxy部分已经包含了脱敏和权限隔离，这是必要的基础。但自演进Agent的安全问题有一个独特性质：恶意或错误的经验一旦被写入长期记忆或技能库，就会跨会话持久化，而不仅仅是一次性的prompt注入。

Zombie Agent 攻击展示了这一机制：攻击者在一次良性会话中通过间接暴露将载荷写入Agent的长期记忆，后续会话中该载荷被检索并触发未授权工具行为。仅靠每会话的prompt过滤不足以防御，因为记忆进化会把一次性注入转化为持久性妥协。

OEP（Obsessive Experience Poisoning） 展示了更隐蔽的变体：攻击者诱导Agent生成“局部正确但不可迁移”的经验，这些经验在语义上合理，但在反思阶段被过度泛化为高风险规则，在GPT-4o Agent上实现了超过50%的攻击成功率，且能绕过LLM审计防御。

SkillJack 则针对“经验→技能”的转化管道：被投毒的经验可以在技能生成阶段被提升为持久化的行为后门，而不仅仅是在检索时生效。

对你的文档意味着什么：在Data Proxy的治理能力之外，需要补一个经验准入与晋升的可信边界。核心原则是：不是所有“看起来正确的经验”都值得被持久化。具体可以包括：

经验写入长期记忆或技能库前，需要独立于生成该经验的会话的验证信号（而非仅靠Agent自我确认）；

来自外部不可信来源（网页、第三方工具返回、用户上传内容）的经验，默认不进入高优先级技能层；

对“经验→技能”的晋升设置比“经验→记忆”更严格的闸门，因为技能是持久化的可执行指令，投毒后果更严重。

⏱️ 补充点四：学习节奏需要“双轨调度”，而非静态的“先快后慢”
你之前已经理解了“快循环 vs 慢循环”的成本分层，但MetaClaw 提供了一个更精细的工程视角：它把进化拆为两条并行的时间尺度，而不是顺序执行。

快轨（秒级） ：Agent碰壁时立即分析失败轨迹，合成自然语言行动指令注入下一次系统Prompt，零宕机起效。慢轨（小时到天级） ：在系统闲置时（如用户睡眠、会议中），将积累的成功轨迹通过LoRA+过程奖励模型蒸馏进权重。

更关键的是它对“奖励污染” 的处理：一旦技能库更新，旧技能环境下的轨迹奖励信号就过期了——用这些数据计算梯度，等于在惩罚模型犯一个已经被新Prompt解决的错误。MetaClaw的解法是严格的技能代际版本控制：失败轨迹仅用于提炼技能后丢弃，只有最新技能下的成功轨迹才进入RL缓冲区。

对你的文档意味着什么：你目前的结构里，快循环和慢循环是“先验证再训练”的顺序关系。可以考虑补充一层调度语义：快循环的每一次技能更新都应该产生一个版本号，慢循环的训练数据必须绑定当前技能版本；跨版本的旧轨迹不进入权重更新，只用于历史统计。这能防止你的RL训练“追赶一个已经不存在的问题”。

🌐 补充点五：跨Agent经验共享——如果你有多个Agent，这是一个被低估的杠杆
你的文档聚焦于单个Agent的自我迭代。如果生产环境中有多个Agent（不同任务、不同租户、不同框架），每个Agent的局部经验是碎片化的。FedAgentKE 提出了一种联邦语义知识进化框架：分布式Agent通过迭代语义知识蒸馏、聚合和适应，在不共享原始轨迹的前提下协同进化可迁移的推理抽象。FederatedSkill 则用语义技能差分作为通信单元，实现隐私保护下的个性化技能进化，平均任务成功率比FedIT提升10%。

对你的文档意味着什么：如果适用，可以在Control Plane的干预面中增加一个跨Agent经验聚合的选项——不是把A的经验直接给B，而是蒸馏为抽象规则或技能差分后，经治理管道分发。这也自然接入了你Data Proxy的租户隔离能力：聚合可以跨Agent，但原始轨迹不跨边界。

🧭 一个结构性建议：补一张“失效模式”对照表
你的文档目前主要在讲“怎么做对”。但自演进系统最大的风险往往来自它以一种看起来在改进的方式变坏。2026年的RSI综述审计了35个系统，发现全部系统都能自主完成执行环节，却没有任何一个能自主设定最终改进目标。这意味着Control Plane的“归因”和“晋升”环节，不能把“目标设定”完全交给Agent自己。
