# 接入全流程示例与避坑指南

> 目标读者：第一次把本项目接入自己业务系统的开发者。
> 主线：**HTTP / SSE 对接**。按本文顺序执行，可以从零跑到「流式对话 + 工具调用 + 人工中断恢复 + 异步任务轮询」。
>
> 文中所有业务名称（如 `research_agent`、`my_tool`）都只是占位示例，
> 仓库代码本身不包含任何行业逻辑。

---

## 0. 接入全景

```text
业务前端 / Java 网关
        │  HTTP + SSE
        ▼
┌──────────────────────────────┐
│ FastAPI（main.py）            │
│  /chat /chat/stream /resume  │
│  /history /async-tasks       │
└──────────────┬───────────────┘
               │ 进程内
               ▼
┌──────────────────────────────┐
│ AgentLoader                  │
│  按 user_id 缓存主 Agent 图   │
└──────┬───────────────┬───────┘
       │               │
       ▼               ▼
 PostgreSQL      OpenSandbox（远端）
 Store/Saver     文件、命令、技能副本
       │
       ▼
 Agent Protocol（异步子 Agent，可选）
 langgraph.json → async_subagent
```

接入分 7 步：

1. 填环境变量；
2. 安装依赖、建库；
3. 构建沙箱镜像并启动 OpenSandbox；
4. 启动 FastAPI；
5. 用 SSE 跑通第一轮对话；
6. 跑通历史、HITL 恢复、异步任务；
7. 加自己的工具 / 子 Agent / 技能。

复制并填写 `.env`：

```dotenv
# 模型
DEEPSEEK_API_KEY=your-key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL_NAME=deepseek-v4-flash

# PostgreSQL

DB_PASSWORD=your-password

# OpenSandbox
OPEN_SANDBOX_API_KEY=your-sandbox-key
OPEN_SANDBOX_HOST=127.0.0.1
OPEN_SANDBOX_PORT=18083
OPEN_SANDBOX_IMAGE=myagent-sandbox:1
OPEN_SANDBOX_PREWARM_ENABLED=true
# Windows / Docker Desktop / 远程服务端场景建议开启
OPEN_SANDBOX_USE_SERVER_PROXY=true

# 异步子 Agent（可选）
HARNESS_ASYNC_AGENT_PROTOCOL_URL=http://127.0.0.1:18082

# FastAPI
HARNESS_API_HOST=127.0.0.1
HARNESS_API_PORT=8000
# 浏览器前端与 API 不同源时填写（逗号分隔）
HARNESS_CORS_ORIGINS=http://127.0.0.1:5173

HARNESS_MCP_CONFIG_PATH=mcp_servers.yaml
```

- 生产环境不要提交真实密钥；`.env` 应只用于本地。

## 3. Step 2：依赖、数据库、沙箱

**安装依赖**

```powershell
uv pip install --python .\.venv\Scripts\python.exe -r requirements.txt
```

**建库**

```sql
CREATE USER harness_user WITH PASSWORD 'your-password';
CREATE DATABASE harness_db OWNER harness_user;
```

`AsyncPostgresStore.setup()` 与 `AsyncPostgresSaver.setup()` 会在首次启动时自动建表。
因此数据库用户需要 `CREATE TABLE` 权限；权限不足时，启动阶段会直接失败，不会静默降级。

**构建沙箱镜像**

```powershell
docker build -t myagent-sandbox:1 sandbox
```

镜像至少需要提供：

- Python 3（技能管理脚本依赖 `PyYAML`）
- `bash` / 常用 Linux 命令
- 如业务需要，再安装 Node / Java / Go 等运行时

字符串 `OPEN_SANDBOX_IMAGE` 必须与 OpenSandbox 服务端可拉取的镜像名一致；本地构建后需要让服务端能访问该镜像。

## 4. Step 3：启动服务

**终端 A：FastAPI**

```powershell
.\.venv\Scripts\python.exe main.py
```

看到 `Uvicorn running on http://127.0.0.1:8000` 即可。

`main.py` 做了两件容易被忽略的事：

1. 把 `src/` 加入 `sys.path`；
2. 在 Windows 上切换为 `WindowsSelectorEventLoopPolicy`（psycopg 异步连接不支持 Proactor）。

**终端 B：Agent Protocol（只有使用异步子 Agent 时才需要）**

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m langgraph_cli dev `
  --config langgraph.json `
  --host 127.0.0.1 --port 18082 `
  --no-browser --no-reload
```

`langgraph.json` 只声明一个图：

```json
{
  "graphs": {
    "async_subagent": "./src/agent/subagents/async_entry.py:async_subagent_graph"
  }
}
```

**启动顺序建议**：PostgreSQL → OpenSandbox → Agent Protocol → FastAPI。
FastAPI 启动时会初始化 Store/Saver、沙箱管理器和只读历史图。

**验收**

```powershell
curl.exe http://127.0.0.1:8000/health
# {"status":"ok"}

curl.exe http://127.0.0.1:8000/openapi.json
```

如果启动失败，优先看这三类错误：

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 连接 PostgreSQL 失败 | 地址/密码错误、数据库不存在、pg_hba 限制 | 先用 `psql` 验证连接 |
| `permission denied for schema public` | 用户无建表权限 | 授权或改由 owner 连接 |
| `Missing credentials` / `未配置 DEEPSEEK_API_KEY` | 模型 Key 未注入 | 检查 `.env` 与外部环境变量 |

## 5. Step 4：跑通第一轮 SSE 对话

### 5.1 最小 curl

```powershell
curl.exe -N -X POST http://127.0.0.1:8000/chat/stream -H "Content-Type: application/json" -d '{"message":"你好，介绍一下你能做什么","user_id":"u_1001","username":"张三"}'
```

PowerShell 5.1 的 `curl` 是 `Invoke-WebRequest` 的别名，必须写 `curl.exe`，否则 `-N` 不生效。

### 5.2 Python 客户端（推荐）

```python
import json

import httpx

BASE = "http://127.0.0.1:8000"


def stream_chat(message: str, user_id: str = "u_1001", thread_id: str | None = None):
    body = {"message": message, "user_id": user_id, "username": "张三"}
    if thread_id:
        body["thread_id"] = thread_id

    with httpx.Client(timeout=None) as client:
        with client.stream("POST", f"{BASE}/chat/stream", json=body) as response:
            response.raise_for_status()
            for line in response.iter_lines():
                if not line.startswith("data: "):
                    continue
                event = json.loads(line[len("data: "):])
                yield event
                if event["type"] == "done":
                    return


for event in stream_chat("你好"):
    print(event)
```

### 5.3 前端状态机

```text
idle
  └─ 发起 /chat/stream
       ├─ token         → 追加文本
       ├─ tool_start    → 新建工具卡片（key=tool_call_id）
       ├─ tool_args     → 更新参数（可能多帧）
       ├─ tool_result   → 填充结果与状态
       ├─ tool_end      → 结束卡片 loading
       ├─ interrupt     → 展示表单，进入 awaiting_human
       ├─ error         → 展示错误，结束本轮
       └─ done          → 关闭连接；若 interrupted=true 则进入 awaiting_human
```

注意：**HTTP 200 不代表成功**。错误可能以 `{"type":"error"}` 事件出现在流里。

### 5.4 非流式接口

```python
response = httpx.post(
    f"{BASE}/chat",
    json={"message": "你好", "user_id": "u_1001"},
    timeout=120,
)
print(response.json()["answer"])
```

非流式适合服务端到服务端调用；需要前端逐字展示时用 SSE。

## 6. Step 5：历史与 HITL 恢复

### 6.1 会话历史

```python
# 创建空会话
session = httpx.post(f"{BASE}/history", params={"user_id": "u_1001"}).json()
thread_id = session["thread_id"]

# 列表
sessions = httpx.get(f"{BASE}/history", params={"user_id": "u_1001"}).json()["sessions"]

# 消息与待处理中断
detail = httpx.get(
    f"{BASE}/history/{thread_id}/messages",
    params={"user_id": "u_1001"},
).json()

# 删除
httpx.delete(f"{BASE}/history/{thread_id}", params={"user_id": "u_1001"})
```

历史恢复是**只读**的：它从 checkpoint 重放消息，不调用模型，也不执行工具。

### 6.2 补充信息中断

触发方式：在子 Agent 的 system prompt 中要求“信息不足时调用 `request_additional_info`”，或 YAML 配置 `interrupt_on`。

SSE 事件示例：

```json
{
  "type": "interrupt",
  "thread_id": "9f0c...",
  "interrupt_id": "int_...",
  "interrupt_type": "information_request",
  "information_needed": "请补充目标时间范围",
  "context": "当前只拿到用户名称"
}
```

恢复：

```python
httpx.post(
    f"{BASE}/chat/{thread_id}/resume",
    json={
        "user_id": "u_1001",
        "resume": {"text": "最近三个月"},
    },
    timeout=None,
)
```

`resume` 的内容会原样成为 `interrupt()` 的返回值。接入方工具需要自己约定字段。

### 6.3 工具审批中断

YAML 配置示例：

```yaml
interrupt_on:
  my_write_tool:
    allowed_decisions: ["approve", "edit", "reject"]
```

SSE 中断：

```json
{
  "type": "interrupt",
  "thread_id": "9f0c...",
  "interrupt_id": "int_...",
  "interrupt_type": "hitl_approval",
  "action_requests": [
    {"name": "my_write_tool", "args": {"id": "123"}, "description": "..."}
  ],
  "review_configs": [
    {"action_name": "my_write_tool", "allowed_decisions": ["approve", "edit", "reject"]}
  ]
}
```

恢复：

```python
httpx.post(
    f"{BASE}/chat/{thread_id}/resume",
    json={
        "user_id": "u_1001",
        "resume": {
            "decisions": [
                {"type": "approve"}
            ]
        },
    },
    timeout=None,
)
```

规则：

- `decisions` 数量与顺序必须和 `action_requests` 一致。
- `edit` 的结构是 `{"type": "edit", "edited_action": {"name": "...", "args": {...}}}`。
- `reject` 可带 `message`，会作为错误返回给模型。
- `respond` 需要工具配置允许，表示由人直接给出工具结果。

## 7. Step 6：异步子 Agent

异步子 Agent 适合“耗时、需要独立上下文、前端可以等待”的任务。

### 7.1 注册

**YAML**：`src/agent/subagents/configs/research_agent.yaml`

```yaml
name: research_agent
description: 负责多步检索与汇总，返回结构化结论。
tools:
  - web_search
system_prompt: |
  你是研究助手。先拆解问题，再逐步检索，最后给出带来源的结论。
```

**注册**：在 `src/agent/subagents/async_registry.py` 中追加

```python
from agent.subagents.async_registry import (
    AsyncSubagentRegistration,
    register_async_subagent,
)
from agent.subagents.configs import config_path


async def _load_research_tools():
    return [web_search]  # 替换为真实工具对象


register_async_subagent(
    AsyncSubagentRegistration(
        name="research_agent",
        description="多步检索与汇总，返回结构化结论。",
        config_path=config_path("research_agent.yaml"),
        tool_loader=_load_research_tools,
        launch_instruction=(
            "当用户需要多步检索、资料汇总或耗时研究时，调用 start_async_task，"
            "subagent_type 填 research_agent，把原始需求完整写入 description。"
        ),
    )
)
```

### 7.2 主 Agent 侧

不需要改 `langgraph.json` 或主 Agent 代码。主 Agent 启动时会读取注册表，自动获得：

- `start_async_task(description, subagent_type)` 工具；
- system prompt 中的委派规则；
- 技能白名单中的子 Agent 名称。

### 7.3 前端轮询

1. 在 SSE 中收到 `tool_result`，`tool_name == "start_async_task"`；
2. 从 `text` 中提取 UUID 形式的 `task_id`；
3. 轮询：

```python
import time

while True:
    status = httpx.get(
        f"{BASE}/async-tasks/{task_id}",
        params={"user_id": "u_1001"},
    ).json()
    if status["done"]:
        break
    time.sleep(3)
```

4. `done=true` 后刷新历史或直接展示 `result`。

服务端会把终态结果**幂等写回主会话**，所以即使前端错过一次轮询，历史里也能看到结果。

## 8. Step 7：加自己的业务能力

### 8.1 加一个本地工具

```python
from langchain_core.tools import tool


@tool
def my_tool(query: str) -> str:
    """一句话说明什么时候用、什么时候不要用。"""
    return f"result for {query}"
```

放到 `src/agent/tools/`，再交给：

- 同步子 Agent：`load_subagent(config_path("x.yaml"), [my_tool])`
- 异步子 Agent：在 `tool_loader` 中返回 `[my_tool]`
- 主 Agent：仅在确实需要主 Agent 直接调用时加入 `main_tools`

### 8.2 加一个同步子 Agent

见 README「三、拓展开发与对接文档 / 一、SubAgent 注册模块」。

### 8.3 加一个技能

```text
src/agent/skills/main/my-skill/
├── SKILL.md
└── metadata.json
```

`SKILL.md`：

```markdown
---
name: my-skill
description: 一句话说明技能用途。
---

# 使用说明

先给约 200 token 的摘要，再写详细流程。
```

`metadata.json`：

```json
{"name": "my-skill", "description": "一句话说明技能用途。"}
```

要点：

- 两个文件的 `name` / `description` 必须完全一致。
- 主 Agent 只发现 `/skills/main/`；子 Agent 只发现自己的 `/skills/subagents/<agent>/`。
- 通过 `assign_skill` 分配是**移动**，不是复制。
- 宿主目录是权威源；不要在沙箱里直接改技能后期待持久化。

### 8.4 MCP 接入（FastMCP）

项目同时提供 MCP 服务端和客户端，支持 `stdio` 与 `streamable_http`。

**服务端**

1. 在 [mcp_server/tools/__init__.py](../src/mcp_server/tools/__init__.py) 的 `register_all_tools` 中注册工具组。
2. 启动：

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m mcp_server.server_main

# stdio 模式
$env:MCP_TRANSPORT = "stdio"
.\.venv\Scripts\python.exe -m mcp_server.server_main
```

默认监听 `http://127.0.0.1:18081/mcp`。

**客户端**

在项目根目录创建 `mcp_servers.yaml`：

```yaml
main_servers:
  - demo_http

servers:
  demo_http:
    transport: streamable_http
    url: http://127.0.0.1:18081/mcp

  local_stdio:
    transport: stdio
    command: python
    args: ["test/mcp_demo_server.py"]
    cwd: .
```

- `main_servers`：主 Agent 构图时自动加载。
- 子 Agent YAML 增加 `mcp_servers: [demo_http]`；`aload_subagent` 会加载对应工具。
- 同步子 Agent 把 YAML 路径放进 `SYNC_SUBAGENT_CONFIG_FILES`，异步子 Agent 的入口已经使用 `aload_subagent`。
- 配置路径用 `HARNESS_MCP_CONFIG_PATH` 覆盖。

**验证**

```powershell
.\.venv\Scripts\python.exe test\test_mcp_integration.py
```

测试会在 `test/mcp_demo_server.py` 启动一个业务无关的 FastMCP 服务，分别验证 stdio 与 HTTP 的工具发现和调用。

**安全边界**

- `stdio` 的 `command` 会在本机执行，`mcp_servers.yaml` 必须是可信文件。
- 跨 Server 的工具重名会直接报错。
- MCP 连接失败会阻断构图，不会静默少加载工具。

### 8.5 加中间件

在 `main_agent.py` 的 `middleware` 列表追加。先想清楚它依赖哪个钩子：

- 需要看本轮输入 → `before_agent`

## 10. 坑位清单

### 10.1 启动与环境

**坑 1：Windows 上 psycopg 报 “ProactorEventLoop is not supported”**

- 原因：Windows 默认事件循环是 Proactor，psycopg 异步连接不支持。
- 处理：用 `main.py` 启动；它会在导入应用前切换 Selector。不要直接用 `uvicorn api.chat:app` 绕开入口。

**坑 2：`.env` 改了但服务还是读旧值**

- 原因：外部环境变量优先（`override=False`），或者进程没重启。
- 处理：确认终端里没有同名环境变量；改完 `.env` 必须重启。

**坑 3：数据库用户没有建表权限**

- 原因：`Store.setup()` / `Saver.setup()` 需要建表。
- 处理：让数据库 owner 连接，或授予 `CREATE` 权限。

**坑 4：`OPEN_SANDBOX_IMAGE` 指向不存在的镜像**

- 现象：请求时报沙箱创建失败或超时。
- 处理：确保镜像已在 OpenSandbox 服务端可见，并确认镜像内有 Python 3 + PyYAML。

**坑 5：没有 `OPEN_SANDBOX_API_KEY`**

- 现象：`/health` 正常；`/chat` 也能回话，但**没有**文件/命令/技能/异步任务能力。
- 原因：沙箱是可选依赖。未配置 Key 时主 Agent 自动降级为「无沙箱纯对话模式」：文件工具落到线程状态（StateBackend），技能同步、技能管理和 `start_async_task` 不装配。
- 处理：需要工具执行能力时配置 `OPEN_SANDBOX_API_KEY` 并重启服务；纯聊天场景可不配。

**坑 5.1：JSON 文件带 UTF-8 BOM 导致启动失败**

- 现象：`langgraph dev` 或技能元数据解析报 `Unexpected UTF-8 BOM`。
- 原因：Windows 下部分编辑器/脚本会把 JSON 写成带 BOM 的 UTF-8。
- 处理：把 `langgraph.json`、`metadata.json` 等 JSON 文件保存为 **UTF-8 无 BOM**。Python 可以用：

```python
from pathlib import Path

path = Path("langgraph.json")
path.write_bytes(path.read_bytes().lstrip(b"\xef\xbb\xbf"))
```

### 10.2 流式与前端

**坑 6：SSE 被反向代理缓冲，前端一直不显示**

- 原因：nginx / 网关默认缓冲响应。
- 处理：关闭 `proxy_buffering`，保留服务端已设置的 `X-Accel-Buffering: no`，并确保 `Content-Type: text/event-stream`。

**坑 7：前端用 axios 读流**

- 原因：axios 默认把响应缓冲成完整字符串。
- 处理：浏览器用 `fetch` + `ReadableStream`；Node 用 `httpx` / `undici` 的流式接口。

**坑 8：只判断 HTTP 状态码**

- 原因：流内错误是 `{"type":"error"}` 事件，HTTP 仍为 200。
- 处理：把所有事件都解析并处理 `error`。

**坑 9：收到 `interrupt` 就关连接**

- 原因：中断需要父图完成 checkpoint；提前关闭会丢恢复点。
- 处理：一直读到 `done`，再根据 `interrupted` 决定是否展示表单。

**坑 10：重复渲染工具卡片**

- 原因：`tool_args` 可能分多帧到达。
- 处理：以 `tool_call_id` 为主键做 upsert，不要每帧新建。

**坑 10.1：浏览器跨域请求被拦截**

- 原因：Vue / 前端与 API 不同源，且未开启 CORS。
- 处理：在 `.env` 设置 `HARNESS_CORS_ORIGINS=http://127.0.0.1:5173`（按实际来源填写），重启服务；生产环境只放行真实域名。

### 10.3 会话与中断

**坑 11：换用户后 `thread_id` 返回 404**

- 原因：会话归属校验按 `user_id`。
- 处理：`user_id` 必须与创建会话时一致；生产环境由网关注入，不能让客户端随意改。

**坑 12：同一会话并发请求返回 409**

- 原因：单进程内对 `thread_id` 做了互斥。
- 处理：前端串行化同一会话的请求；不要用多 worker 规避（见坑 20）。

**坑 13：resume 用错中断 ID**

- 原因：流里可能先看到子图中断，之后父图 checkpoint 才落最终中断。
- 处理：用 `interrupt` 事件里的 `interrupt_id`；服务端已做 canonical 化，前端不要自己拼。

**坑 14：审批 decisions 数量不对**

- 原因：一次中断可能包含多个 `action_requests`。
- 处理：按顺序为每个 action 生成一个 decision。

**坑 15：补充信息后模型仍然说缺信息**

- 原因：`resume` 的字段与工具约定不一致，或模型没理解。
- 处理：在工具 docstring 和 system prompt 中写清楚 resume 的字段结构。

### 10.4 异步子 Agent

**坑 16：`start_async_task` 报未知子 Agent**

- 原因：注册表为空、名称拼错，或注册代码没有被导入。
- 处理：确认 `register_async_subagent` 在 `async_registry.py` 模块级执行；重启主 Agent 进程。

**坑 17：远程图报缺少 `subagent_name` / `sandbox_id`**

- 原因：调用 `runs.create` 时 `context` 不完整。
- 处理：主 Agent 的 `start_async_task` 已自动携带两者；自研调用方必须同时传。

**坑 18：Agent Protocol 启动失败或找不到 `agent` 包**

- 原因：`langgraph_cli` 不继承 `main.py` 的 `sys.path`。
- 处理：启动前设置 `$env:PYTHONPATH="$PWD\src"`。

**坑 19：改了子 Agent 代码但远程图没生效**

- 原因：`--no-reload` 不热加载。
- 处理：重启 Agent Protocol 进程。

**坑 20：异步任务永远 `running`**

- 原因：Agent Protocol 没启动，或 `HARNESS_ASYNC_AGENT_PROTOCOL_URL` 指错。
- 处理：先访问 `http://127.0.0.1:18082/ok`，确认服务存活。

**坑 21：`delivered=false`**

- 原因：主会话正在中断中，或写入失败。
- 处理：等主会话恢复后重试轮询；服务端写入是幂等的。

### 10.5 工具、技能与上下文

**坑 22：YAML 声明的工具启动时报缺工具**

- 原因：工具对象的 `.name` 与 YAML 不一致。
- 处理：用 `tool.name` 对齐；异步加载的工具要在 `load_subagent` 之前 `await` 完成。

**坑 23：技能 `SKILL.md` 与 `metadata.json` 不一致**

- 原因：手工改了一个文件。
- 处理：两个文件必须同步；`skill-management` 是保留名，不能分配或删除。

**坑 24：在沙箱里改技能，下次 run 被覆盖**

- 原因：宿主是权威源，每次 run 前都会增量同步。
- 处理：改宿主 `src/agent/skills/`；沙箱只作为运行副本。

**坑 25：`/memories/` 写到了沙箱**

- 原因：路径前缀不匹配。
- 处理：持久化只写 `/memories/{user_id}/...`；其他路径都是沙箱临时文件。

**坑 26：模型循环或工具风暴导致任务被截断**

- 原因：`ModelCallLimit` / `ToolCallLimit` 达到上限。
- 处理：调整 `src/agent/config.py` 的预算，或在 prompt 中要求先规划再执行。

**坑 27：主 Agent 直接调业务写工具**

- 原因：工具挂错层级。
- 处理：业务读写工具只挂到子 Agent；主 Agent 只保留通用能力。

### 10.6 部署

**坑 28：多 worker 部署后会话互斥失效**

- 原因：`AgentLoader` 的会话锁与 Agent 缓存是进程内状态。
- 处理：当前只支持单 worker；多 worker 需要引入分布式锁和共享缓存。

**坑 29：`langgraph dev` 用于生产**

- 原因：`dev` 是开发服务器。
- 处理：生产用 LangGraph Server / 自建 Agent Protocol 部署方式，并按官方文档配置持久化与并发。

**坑 30：把身份交给客户端自报**

- 原因：模板不做认证。
- 处理：在网关完成登录校验，把可信的 `user_id` / `username` 覆盖进请求；禁止直接透传前端提交的身份字段。

### 10.7 MCP 接入

**坑 31：`mcp_servers.yaml` 不存在，以为 MCP 已启用**

- 原因：默认配置不存在时，加载器按“未接入 MCP”处理，返回空工具列表。
- 处理：确认项目根目录有 `mcp_servers.yaml`，或设置 `HARNESS_MCP_CONFIG_PATH`。

**坑 32：stdio 的 `command` 找不到**

- 原因：`command` 用了相对路径或当前进程 PATH 里没有该解释器。
- 处理：写绝对路径，例如 `sys.executable`；Windows 上优先使用 `.venv\Scripts\python.exe`。

**坑 33：HTTP MCP 连接失败**

- 原因：服务未启动、URL 少了 `/mcp`、端口不一致。
- 处理：先访问 `http://127.0.0.1:18081/mcp` 确认服务监听；客户端 `url` 必须带 `/mcp`。

**坑 34：多个 MCP Server 工具重名**

- 原因：不同 Server 都暴露了 `search` 之类的通用名。
- 处理：在 Server 侧改成带命名空间的名字（如 `order_search`）；当前加载器检测到重名会直接报错。

**坑 35：子 Agent 声明了 `mcp_servers` 但工具没加载**

- 原因：使用了静态 `load_subagent`，它不会异步加载 MCP。
- 处理：同步子 Agent 用 `SYNC_SUBAGENT_CONFIG_FILES`（内部走 `aload_subagent`）；异步子 Agent 的入口已自动使用 `aload_subagent`。

**坑 36：stdio MCP Server 往 stdout 打印日志**

- 原因：MCP stdio 协议占用 stdout，任何非协议输出都会破坏消息流。
- 处理：日志写 stderr，或直接使用 Streamable HTTP。

## 11. 接入后的观测与评估建议

按“先可观测、再优化”的顺序：

1. **Trace**：给主图和远程图接入 Langfuse（自托管）或 LangSmith。至少记录：`thread_id`、`user_id`、模型调用、工具名、耗时、错误。
2. **评估集**：把线上失败的 `thread_id` 转成固定输入用例，覆盖：正常问答、工具失败自纠、HITL 恢复、异步任务超时。
3. **回归门禁**：用 DeepEval + pytest 跑步骤级断言（工具是否选对、是否重复调用、最终答案是否包含关键结论）。
4. **成本观察**：记录每次 run 的模型调用次数、工具调用次数、token 用量。先设预算上限，再谈优化。

没有 trace 和评估集之前，不建议大改 prompt、压缩阈值或子 Agent 拆分——那只是盲改。
