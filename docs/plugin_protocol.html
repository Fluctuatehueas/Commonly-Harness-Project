Harness 插件协议 1.0

本页是 Harness 插件系统的对外协议文档。按本页实现即可用任意语言接入， 不依赖任何 SDK：只要进程能读写 stdin/stdout，或者能提供 HTTP POST 端点。 后续 C# / TypeScript 官方 SDK 文档会追加到第 12 节，协议部分保持不变。

Protocol 1.0 JSON-RPC 2.0 stdio / http / sandbox_stdio C# / Java / TS / JS / Python 均可

00概览

Harness 把插件当作「外设」：Agent 是 CPU，Harness 是主板，Plugin Bus 是外设总线。 插件通过统一协议接入，崩溃、超时或卸载只影响单个外设，不阻断对话主流程。

握手initialize → describe → 可用
调用tool.call / resource.* / prompt.get / hook.invoke
反向仅 host.storage / secret / log / progress
隔离独立进程；不继承宿主环境变量

一次完整生命周期

总线 插件进程 | spawn / POST | |-- plugin.initialize -------------------->| 校验 protocolVersion，保存 config |<------------------------- {"ok": true} | |-- plugin.describe ---------------------->| 上报 capabilities |<------------------- {"capabilities":…} | | | | （能力写入注册表，工具注入 Agent） | | | |-- tool.call {name, arguments} ---------->| 执行业务 |<---------------------- {"content": "…"} | | | | （空闲 300s 回收 / 崩溃退避重启） |

三条硬边界

  • 总线只做握手、权限、生命周期与路由，不理解插件业务。
  • 插件只能看到 manifest 声明的能力与 host.* 白名单，不持有宿主对象。
  • 任何插件故障都必须降级：工具调用返回结构化错误，hook 异常只跳过，UI 失败只影响该 slot。

01快速开始

最小可运行插件只需要一个 manifest.json 和一个能按行读写 JSON 的入口程序。

第 1 步：写 manifest.json

把 manifest 放在插件包根目录，runtime.command 指向入口程序。

{
  "plugin_id": "echo-plugin",
  "name": "回显插件",
  "version": "1.0.0",
  "protocolVersion": "1.0",
  "description": "最小示例：把输入原样返回。",
  "author": { "name": "Local" },
  "license": "MIT",
  "tag": ["示例"],
  "source": "user",
  "capabilities": ["tool"],
  "runtime": {
    "kind": "subprocess",
    "language": "python",
    "command": "python",
    "args": ["plugin.py"]
  },
  "transport": { "kind": "stdio" },
  "permissions": [],
  "harnessVersion": { "min": "1.1.0", "max": "1.x" }
}

第 2 步：实现 4 个方法

最少需要 plugin.initialize、plugin.describe、plugin.health、 tool.call。完整骨架见 第 11 节。

第 3 步：本地自测

直接向 stdin 灌一行握手请求，看 stdout 是否返回一行 JSON：

'{"jsonrpc":"2.0","id":"1","method":"plugin.initialize","params":{}}' | python plugin.py
echo '{"jsonrpc":"2.0","id":"1","method":"plugin.initialize","params":{}}' | python plugin.py
自测只验证帧格式。真正的握手会带 protocolVersion、user_id、 permissions 与 config，见 第 5 节。

第 4 步：打包

把 manifest 与代码打成 ZIP，manifest.json 必须在包根目录（不能多套一层文件夹）：

plugin.zip
├── manifest.json
├── plugin.py
└── ui/            # 可选，声明 ui 能力时提供

第 5 步：安装

控制台「插件 → 上传插件包」，或调用管理接口：

POST /plugins/install/upload    multipart: file=plugin.zip
POST /plugins/install           {"source":"url","url":"https://…/plugin.zip","sha256":"…"}

安装是异步任务，返回 job_id；阶段依次为 queued → downloading → scanning → sandbox_verifying → extracting → installing → starting → done。

02manifest 规范

manifest 是插件对外的唯一描述：市场展示、安装校验、握手与能力注入都读它，不存在第二套字段。

字段表

字段必填说明
plugin_id必填^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$，同一来源内唯一
name必填展示名称
version必填semver，如 1.0.0
protocolVersion必填MAJOR.MINOR，当前只接受 1.0
author.name必填不允许匿名发布
capabilities必填六类能力的子集，不能为空
runtime必填kind ∈ subprocess / remote / inprocess（仅内置）
transport可选stdio / http；缺省按 runtime 推导
permissions可选未声明即无权限，不做隐式放行
description可选市场卡片摘要来源
license / tag / source可选展示与筛选字段
env可选运行环境要求，不负责安装依赖
ui.slots[]声明 ui 时必填{slot, title, entry}，entry 为包内相对路径
harnessVersion可选{min, max}，默认 1.1.0 ~ 1.x
configSchema可选JSON Schema，前端通用渲染配置表单
dist市场条目必填{url, sha256, size}；本地 ZIP 安装以实际包哈希为准

远程插件

{
  "runtime": { "kind": "remote" },
  "transport": { "kind": "http", "url": "https://example.com/plugin/rpc" }
}

校验规则

  • version 必须是 semver；protocolVersion 主版本必须为 1。
  • 未知能力或未知权限直接拒绝安装，不做兼容猜测。
  • 声明 ui 能力时必须同时提供 ui.slots 并声明 ui 权限。
  • runtime.kind=inprocess 只允许系统内置插件；项目级插件强制沙箱运行。
  • harnessVersion 不覆盖当前宿主版本时，安装阶段即拒绝。

03传输与帧格式

传输适用要点
stdio本地子进程插件一行一条 JSON；stdout 只走协议；stderr 落 logs/stdio.log
http远程服务接入每次请求一个 POST，body 为 JSON-RPC 信封；可选 SSE 预留
sandbox_stdio项目级 / 高风险插件每次调用在沙箱内拉起一次性进程，不常驻、不心跳
inprocess系统内置插件宿主进程内调用，不对外开放

stdio 帧规则

  • UTF-8 编码，一行一条消息，以 \n 分隔；单行上限 8 MB。
  • stdout 只能写协议消息；日志一律写 stderr，否则会污染协议导致解析失败。
  • 输出后立即 flush，否则宿主读不到响应，表现为调用超时。
  • 宿主只透传白名单环境变量：PATH、LANG、LC_ALL、TMPDIR、TEMP、TMP、SYSTEMROOT，并设置 PYTHONPATH=插件目录、PYTHONUNBUFFERED=1。
  • 工作目录固定为插件版本目录：plugins/users/{uid}/{plugin_id}/versions/{version}/。
  • 进程退出时，在途请求统一返回 PLUGIN_CRASHED；插件应处理 stdin EOF 并自行退出。

http 传输规则

  • 请求：POST {transport.url}，Content-Type: application/json，body 为完整 JSON-RPC 信封。
  • 响应：JSON-RPC 信封；HTTP 非 2xx 视为 PLUGIN_TOOL_FAILED。
  • 连接超时 15s，请求超时按方法分别为 5s~60s。
  • 远程插件没有反向通道，host.* 不可用；需要外部凭据时用配置字段，不要试图读取宿主环境。

sandbox_stdio 规则

  • 每次工具调用都会在沙箱内完成 initialize → describe → tool.call → 退出。
  • 不保持内存状态；需要持久化的数据请放插件数据文件或调用时传入。
  • 项目级插件目录：<project_root>/.commonharness/plugins/{plugin_id}/，只在沙箱内运行。

04JSON-RPC 信封

遵循 JSON-RPC 2.0。请求、成功响应、错误响应、通知四种形态：

// 请求（总线 → 插件）
{ "jsonrpc": "2.0", "id": "req-1", "method": "tool.call", "params": { "name": "echo", "arguments": { "text": "hi" } } }

// 成功响应
{ "jsonrpc": "2.0", "id": "req-1", "result": { "content": "hi" } }

// 错误响应
{ "jsonrpc": "2.0", "id": "req-1", "error": { "code": -32010, "message": "工具执行失败" } }

// 通知（无 id，不需要响应）
{ "jsonrpc": "2.0", "method": "host.log", "params": { "level": "info", "message": "ready" } }
  • id 由宿主生成（32 位十六进制），插件必须原样回传；通知不带 id。
  • 通知只用于 host.log / host.progress / event.notify，宿主不会回包。
  • 请求 params 必须是对象；不是对象的请求按 -32602 拒绝。
  • 插件收到的未知响应（无 method）直接忽略即可。

05总线调用插件

方法用途默认超时失败策略
plugin.initialize握手15s拒绝启用，标记 unhealthy
plugin.describe上报能力15s与 manifest 不一致则握手失败
plugin.health健康探针（每 30s）5s连续失败计入 unhealthy
plugin.shutdown优雅退出（协议预留）5s超时由宿主结束进程
tool.call调用工具60s返回错误，不影响其他工具
resource.list列举资源15s返回空并标记降级
resource.read读取资源正文30s返回错误
prompt.get取提示词片段10s跳过注入
hook.invoke拦截点回调3s记录并跳过，不阻断
event.notify总线推事件（通知）不等待忽略失败

plugin.initialize

参数（宿主 → 插件）：

{
  "protocolVersion": "1.0",
  "plugin_id": "echo-plugin",
  "version": "1.0.0",
  "user_id": "user-123",
  "permissions": ["storage"],
  "config": { "endpoint": "https://…" }
}

config 是用户在插件详情页保存的非敏感配置。密钥通过 host.secret.get 获取， 不会出现在 initialize 里。返回任意 JSON 即可，建议 {"ok": true}； 宿主只关心是否成功与是否超时。

plugin.describe

参数为空对象。返回值必须包含 capabilities 对象，其类型必须是 manifest 声明的子集：

{
  "plugin_id": "echo-plugin",
  "protocolVersion": "1.0",
  "version": "1.0.0",
  "capabilities": {
    "tool": [
      {
        "name": "echo",
        "description": "把输入原样返回",
        "inputSchema": {
          "type": "object",
          "properties": { "text": { "type": "string", "description": "待回显的文本" } },
          "required": ["text"]
        }
      }
    ],
    "resource": [
      { "uri": "demo://readme", "name": "说明", "mimeType": "text/markdown" }
    ],
    "prompt": [
      { "id": "style", "trigger": "keyword", "keywords": ["风格", "格式"] }
    ],
    "hook": [
      { "name": "before_tool", "priority": 100 }
    ],
    "ui": [
      { "slot": "chat.sidebar", "title": "回显面板", "entry": "ui/index.html" }
    ]
  }
}
  • 上报了 manifest 未声明的能力类型 → PLUGIN_CAPABILITY_MISMATCH，握手失败。
  • 工具对外暴露名统一加前缀：plugin__{plugin_id}__{name}，避免与内置工具、MCP 冲突。
  • hook.name 只能是 before_model / after_model / before_tool / after_tool；priority 越小越先执行，默认 100。
  • prompt.trigger 支持 always / keyword / capability；提示词总长上限 2000 字符。

plugin.health

参数为空对象；只要正常返回（任意 JSON）即视为健康。超时或异常计入失败次数。

plugin.shutdown

协议已定义该方法的语义（5s 内退出），但当前宿主停止插件时以关闭连接/结束进程为主， 不会保证先发 plugin.shutdown。请同时实现stdin EOF 退出兜底， 需要持久化的状态写入 host.storage 或插件数据文件。

tool.call

参数：

{ "name": "echo", "arguments": { "text": "hello" } }

返回值（content 会被直接作为工具结果文本展示给 Agent）：

{ "content": "hello" }
或直接返回字符串："hello"
或返回任意对象（宿主会 JSON 序列化）：{ "value": 42 }

工具名只允许调用 describe 中声明过的工具；否则返回 PLUGIN_PERMISSION_DENIED。

resource.list / resource.read

// resource.list 参数：{}
// 返回：[{ "uri": "demo://readme", "name": "说明", "mimeType": "text/markdown" }]

// resource.read 参数：
{ "uri": "demo://readme" }
// 返回：字符串或对象，由宿主交给 plugin_resource_read 工具

prompt.get

// 参数：{ "id": "style" }
// 返回：提示词正文（字符串）

hook.invoke

参数结构 { "hook": "<name>", "payload": { … } }。各 hook 的 payload 与返回值：

hookpayload返回值约定
before_model { messages: [{role, content}], system_prompt }（各字段截断） 忽略返回值；只做观测或副作用
after_model { messages: [{role, content}] }（最近 5 条） 忽略返回值
before_tool { tool, arguments } 可返回 {"allow": false, "reason": "…"} 拒绝执行
after_tool { tool, arguments, result } 可返回 {"content": "改写后的结果"}

hook 超时 3s，异常或超时只写轨迹并跳过，不影响主流程。

event.notify

协议预留的通知方法，用于总线向插件推送配置变更、启停等事件（无 id）。 当前版本宿主不主动发送；插件收到未知通知应忽略而不是报错。

06插件回调宿主（host.*）

只开放四个命名空间，且必须在 manifest 声明对应权限；未声明即拒绝。

方法所需权限参数返回
host.storage.getstorage{ "key": "…" }任意 JSON 或 null
host.storage.setstorage{ "key": "…", "value": … }{ "ok": true }
host.storage.liststorage{}键名数组
host.storage.deletestorage{ "key": "…" }{ "ok": true }
host.secret.getsecret{ "name": "…" }密钥明文（仅在本次连接内有效）
host.log无{ "level": "info", "message": "…" }{}
host.progress无{ "current": 1, "total": 3, "message": "…" }{ "ok": true }

示例：插件请求宿主写入一个键值

{ "jsonrpc": "2.0", "id": "p-1", "method": "host.storage.set",
  "params": { "key": "counter", "value": 3 } }

// 宿主响应
{ "jsonrpc": "2.0", "id": "p-1", "result": { "ok": true } }
  • host.storage.* 是插件私有数据目录下的单文件 JSON KV（data/kv.json）， 不接受任意路径；key 为空会被拒绝。
  • host.secret.get 读取的是用户级密钥环境变量 HARNESS_PLUGIN_SECRET_{PLUGIN_ID}_{NAME}；未配置返回错误。
  • host.log 写入插件日志文件，单条消息截断 4000 字符；超过 5 MB 轮转。
  • 超过 host.* 白名单的方法（例如读宿主文件、起进程、读环境变量）一律拒绝，没有例外。
http 与 sandbox_stdio 传输没有反向通道，host.* 调用会直接失败。 这类插件应把外部凭据放进配置字段，或在自身服务侧管理。

07六类能力

能力总线侧Agent / 控制台如何看到
tooltool.call 路由、超时、权限注入主 Agent 工具清单，名称 plugin__{plugin_id}__{name}
resourceresource.list / resource.read资源目录进系统提示，正文通过 plugin_resource_read 读取
promptprompt.get按 always / keyword / capability 注入系统提示
hookhook.invoke中间件拦截点，超时或异常降级
ui静态资源路由 + slot 注册控制台 slot 内沙箱 iframe，不进入主 bundle
integration复用 tool / resource + 凭据安装时逐条确认外部系统权限

UI slot

首批 slot：chat.sidebar、chat.composer.after、console.plugin.detail。约束：

  • iframe 使用 sandbox="allow-scripts allow-forms"，不开放 allow-same-origin。
  • 只接受白名单消息：plugin:ready、plugin:resize、plugin:event，并校验来源。
  • 静态资源由 GET /plugins/{id}/ui/{path} 提供，只服务已启用插件，路径穿越拒绝。
  • slot 加载失败只显示「插件界面不可用」，不影响主页面。

08错误码

JSON-RPC 标准码保留，业务错误使用 -32001 ~ -32010。

码名称含义管理面 HTTP
-32700PLUGIN_PARSE_ERROR消息不是合法 JSON400
-32600PLUGIN_INVALID_REQUEST信封结构非法400
-32601PLUGIN_METHOD_NOT_FOUND未知方法404
-32602PLUGIN_INVALID_PARAMS参数类型或必填缺失422
-32603PLUGIN_INTERNAL_ERROR插件内部异常500
-32001PLUGIN_NOT_FOUND插件不存在404
-32002PLUGIN_NOT_READY未握手、已停用或正在重启503
-32003PLUGIN_PERMISSION_DENIED未声明权限或越权调用403
-32004PLUGIN_TIMEOUT调用超时504
-32005PLUGIN_CAPABILITY_MISMATCHdescribe 与 manifest 不一致422
-32006PLUGIN_PROTOCOL_VERSION_MISMATCH协议主版本不兼容422
-32007PLUGIN_CRASHED插件进程退出 / 连接断开502
-32008PLUGIN_UNHEALTHY连续健康检查失败503
-32009PLUGIN_PACKAGE_INVALID包结构、哈希或解压不安全422
-32010PLUGIN_TOOL_FAILED工具执行失败400 / 500

插件返回错误时只需给出 code 与 message，宿主会记录到轨迹与审计，不会把内部堆栈透给用户。

09版本协商

  • 协议版本 protocolVersion：MAJOR.MINOR。主版本不同直接拒绝握手； 次版本只允许不高于总线支持的版本（当前支持 1.0）。
  • 插件版本 version：semver，管功能迭代与更新回滚。
  • 宿主版本 harnessVersion：{min, max}，max 支持 1.x。 不覆盖当前宿主时在安装阶段拒绝，不进入握手。
两条版本轴互不替代：协议版本管「能不能通信」，插件版本管「功能是不是最新」。 协议不兼容时不要尝试兼容猜测，直接返回 -32006。

10安全边界

  • 宿主侧子进程是同等权限的独立进程，不是 OS 级隔离。v1.1 依靠「装前沙箱验证 + 运行时声明权限」收口。
  • 不继承宿主环境变量，尤其不传递模型 API Key、数据库密码与宿主配置。
  • 插件依赖不自动安装到宿主环境：依赖必须随包携带，或声明为沙箱依赖。
  • 四道闸门：声明权限 → 静态扫描 → 沙箱试运行 → 用户确认。路径穿越、符号链接、危险调用会被标记或拒绝。
  • UI 只能在沙箱 iframe 内渲染，不开放同源，不允许直接操作主前端 DOM。
  • 审计：安装、启停、重启、更新、卸载、验证、权限与配置变更都写入 plugin_audit。
不要把密钥写进 manifest 或代码。manifest 与配置只允许保留引用， 运行时通过 host.secret.get 获取；远程插件请自行管理凭据。

11五语言最小实现

以下骨架都实现同一个最小插件：一个 echo 工具，外加握手、健康检查与退出。 复制后补上自己的业务逻辑即可。共同约定：一行一条 JSON、stdout 只写协议、日志写 stderr。 

import json
import sys


def send(message):
    sys.stdout.write(json.dumps(message, ensure_ascii=False) + "\n")
    sys.stdout.flush()


def describe():
    return {
        "capabilities": {
            "tool": [
                {
                    "name": "echo",
                    "description": "把输入原样返回",
                    "inputSchema": {
                        "type": "object",
                        "properties": {"text": {"type": "string"}},
                        "required": ["text"],
                    },
                }
            ]
        }
    }


def handle(method, params):
    if method == "plugin.initialize":
        # params: protocolVersion / plugin_id / user_id / permissions / config
        return {"ok": True}
    if method == "plugin.describe":
        return describe()
    if method == "plugin.health":
        return {"ok": True}
    if method == "plugin.shutdown":
        return {"ok": True}
    if method == "tool.call":
        if params.get("name") != "echo":
            raise ValueError("unknown tool")
        arguments = params.get("arguments") or {}
        return {"content": str(arguments.get("text", ""))}
    raise ValueError(f"unknown method: {method}")


for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    try:
        message = json.loads(line)
    except json.JSONDecodeError:
        continue
    if "method" not in message:   # 忽略宿主返回的响应
        continue
    request_id = message.get("id")
    try:
        result = handle(message["method"], message.get("params") or {})
        if request_id is not None:
            send({"jsonrpc": "2.0", "id": request_id, "result": result})
    except Exception as error:
        print(f"tool failed: {error}", file=sys.stderr)
        if request_id is not None:
            send({"jsonrpc": "2.0", "id": request_id,
                  "error": {"code": -32010, "message": str(error)}})

    },
  }
}

  switch (method) {
    case 'plugin.initialize':
      return { ok: true }
    case 'plugin.describe':
      return describe()
    case 'plugin.health':
    case 'plugin.shutdown':
      return { ok: true }
    case 'tool.call': {

      const args = (params.arguments ?? {}) as Json
      return { content: String(args.text ?? '') }
    }
    default:
      throw new Error(`unknown method: ${method}`)
  }
}

using System;
using System.Text.Json.Nodes;

Console.InputEncoding = System.Text.Encoding.UTF8;
Console.OutputEncoding = System.Text.Encoding.UTF8;

static void Send(JsonObject message)
{
    Console.Out.WriteLine(message.ToJsonString());
    Console.Out.Flush();
}

static JsonObject Describe() => JsonNode.Parse("""
{
  "capabilities": {
    "tool": [{
      "name": "echo",
      "description": "把输入原样返回",
      "inputSchema": {
        "type": "object",
        "properties": { "text": { "type": "string" } },
        "required": ["text"]
      }
    }]
  }
}
""")!.AsObject();

static JsonNode Handle(string method, JsonObject parameters)
{
    switch (method)
    {
        case "plugin.initialize":
            return new JsonObject { ["ok"] = true };
        case "plugin.describe":
            return Describe();
        case "plugin.health":
        case "plugin.shutdown":
            return new JsonObject { ["ok"] = true };
        case "tool.call":
        {
            if (parameters["name"]?.GetValue<string>() != "echo")
                throw new InvalidOperationException("unknown tool");
            var arguments = parameters["arguments"]?.AsObject() ?? new JsonObject();
            return new JsonObject { ["content"] = arguments["text"]?.ToString() ?? "" };
        }
        default:
            throw new InvalidOperationException($"unknown method: {method}");
    }
}

while (Console.In.ReadLine() is { } line)
{
    if (string.IsNullOrWhiteSpace(line)) continue;
    JsonObject message;
    try { message = JsonNode.Parse(line)!.AsObject(); }
    catch { continue; }
    if (!message.ContainsKey("method")) continue;

    var id = message["id"]?.DeepClone();
    try
    {
        var result = Handle(
            message["method"]!.GetValue<string>(),
            message["params"]?.AsObject() ?? new JsonObject());
        if (id is not null)
            Send(new JsonObject { ["jsonrpc"] = "2.0", ["id"] = id, ["result"] = result });
    }
    catch (Exception error)
    {
        Console.Error.WriteLine(error);
        if (id is not null)
        {
            Send(new JsonObject
            {
                ["jsonrpc"] = "2.0",
                ["id"] = id,
                ["error"] = new JsonObject { ["code"] = -32010, ["message"] = error.Message },
            });
        }
    }
}
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.nio.charset.StandardCharsets;
import org.json.JSONObject;

public final class PluginMain {
    public static void main(String[] args) throws Exception {
        var reader = new BufferedReader(
            new InputStreamReader(System.in, StandardCharsets.UTF_8));
        var out = new PrintWriter(
            new OutputStreamWriter(System.out, StandardCharsets.UTF_8));

        String line;
        while ((line = reader.readLine()) != null) {
            if (line.isBlank()) continue;
            JSONObject message;
            try { message = new JSONObject(line); }
            catch (Exception ignored) { continue; }
            if (!message.has("method")) continue;

            Object id = message.opt("id");
            try {
                JSONObject params = message.optJSONObject("params");
                JSONObject result = handle(message.getString("method"),
                                            params == null ? new JSONObject() : params);
                if (id != null) {
                    out.println(new JSONObject()
                        .put("jsonrpc", "2.0")
                        .put("id", id)
                        .put("result", result));
                    out.flush();
                }
            } catch (Exception error) {
                System.err.println(error.toString());
                if (id != null) {
                    out.println(new JSONObject()
                        .put("jsonrpc", "2.0")
                        .put("id", id)
                        .put("error", new JSONObject()
                            .put("code", -32010)
                            .put("message", error.getMessage())));
                    out.flush();
                }
            }
        }
    }

    private static JSONObject handle(String method, JSONObject params) throws Exception {
        switch (method) {
            case "plugin.initialize":
                return new JSONObject().put("ok", true);
            case "plugin.describe":
                return new JSONObject("""
                    {"capabilities":{"tool":[{
                      "name":"echo",
                      "description":"把输入原样返回",
                      "inputSchema":{"type":"object",
                        "properties":{"text":{"type":"string"}},
                        "required":["text"]}
                    }]}}
                    """);
            case "plugin.health":
            case "plugin.shutdown":
                return new JSONObject().put("ok", true);
            case "tool.call": {
                if (!"echo".equals(params.optString("name")))
                    throw new IllegalArgumentException("unknown tool");
                JSONObject arguments = params.optJSONObject("arguments");
                return new JSONObject().put("content",
                    arguments == null ? "" : arguments.optString("text"));
            }
            default:
                throw new IllegalArgumentException("unknown method: " + method);
        }
    }
}

13常见坑点

  1. stdout 被打日志污染：任何 print / console.log 都会破坏协议帧。日志一律写 stderr。
  2. 忘记 flush：缓冲导致宿主读不到响应，表现为「第一次调用必超时」。每次写完立即 flush。
  3. 路径多套一层：ZIP 里必须是 manifest.json 在根，不要 plugin/manifest.json。
  4. describe 与 manifest 不一致：manifest 声明 tool，describe 却上报 resource，握手直接失败。
  5. 协议版本写错：protocolVersion 只能是 1.0；1.0.0 会被判为格式非法。
  6. Windows 编码：C# / Java 要显式设 UTF-8，否则中文参数乱码。
  7. 试图自动重试 tool.call：业务可能非幂等，SDK 与宿主都不会自动重试；只读的 host.storage.get/list 可重试一次。
  8. 远程插件调用 host.*：HTTP 没有回调通道，必然失败。凭据请放配置字段。
  9. 把大对象塞进工具结果：工具结果会进 Agent 上下文，建议只返回必要文本，复杂数据让插件自己落文件。
  10. 项目级插件想常驻：项目级强制沙箱一次性进程，不保持内存状态。
